第 1 课：先证明环境可调试

本课只建立“代码能运行、测试能失败、断点能停住”三个事实。暂时不接入 LLM，也不引入 Cordis。

本课导览

包含内容Bun 与 TypeScript 环境、最小程序、自动测试、VS Code 断点调试。
涉及模块package.json、tsconfig.json、基线源码与测试、VS Code 调试配置。
白话解释先把实验台搭稳：代码确实能跑，写错时测试确实会红，需要观察时断点确实能停。
解决的问题排除环境和工具链噪声，避免后续把安装、编译或调试问题误判成 Harness 设计问题。

完整能力清单

能力具体覆盖完成标志
运行基线Bun 运行 TypeScript 源码，入口能够稳定退出并返回正确退出码。示例输出可重复。
类型基线严格类型检查覆盖源码与测试，类型错误在运行前暴露。tsc 无错误。
测试基线测试可通过，也能通过故意修改断言证明失败路径有效。bun:test 能红能绿。
调试基线VS Code 可启动目标、命中源码断点并检查局部变量与调用栈。按 F5 能停在断点。

当前基线

Bun1.3.14，同时承担运行时、包管理器、测试器和调试入口
TypeScript5.9.3，由 bun x tsc 执行严格类型检查
依赖只有 TypeScript 与 Bun 类型声明两个开发依赖，无运行时三方包
构建产物Bun 运行源码；发布时生成 JS、声明文件与 source map

练习

  1. 进入 harness-lab。
  2. 运行 bun install。
  3. 运行 bun run typecheck，证明严格类型检查通过。
  4. 选择一个最小测试，用 bun test src/context.test.ts 执行。
  5. 使用下面的命令启动断点调试，并在测试源码第一行设置断点。
cd harness-lab
bun install
bun run typecheck

# Bun Inspector 启动后先停在入口；单并发让断点顺序稳定
