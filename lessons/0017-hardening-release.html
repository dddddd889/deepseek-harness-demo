完整能力清单

能力域完整能力不能替代什么
会话遥测禁用、仅反馈和完整三种模式；选择事件、设置严重级别、脱敏并隔离导出失败。不能替代 Session 事实日志。
OTel Logs把选定会话事件转换为可检索、关联和告警的观测记录并送往 Collector。不能用于会话恢复、分叉或权威计费。
反馈导出仅反馈模式在用户提交反馈后导出对应记录，避免默认采集完整会话。不能绕过脱敏与采集策略。
成本投影按请求时刻匹配提供方、模型和生效价格，将互斥用量桶计算为高精度美元成本。未知模型进入未定价列表，不能默认为零成本。
运行能力探测探测平台、真实伪终端、强沙箱和进程隔离，并提供强制能力检查。不支持的强能力不能静默降级。
热重载先完整启动候选插件包，成功后原子切换，再释放旧包。候选失败时旧能力继续服务，不发生闪断。
故障注入在指定命中次数稳定触发异常或延迟，用于复现提供方和传输故障。只影响明确配置的故障点和次数。
发布验收类型检查、完整测试、构建、CLI 帮助、冒烟运行和资源收敛检查。单个成功演示不能替代整套发布门禁。

生产证据链
├─ telemetry disabled → 不导出
├─ feedback-only → 用户反馈后导出关联记录
├─ full → 选择事件、脱敏、导出

└─ release gate 任一失败 → 不发布
场景系统行为不能做的事
遥测后端宕机记录导出失败并继续追加会话事实。不能让观测系统成为业务单点。
敏感会话禁用或仅反馈采集，并应用字段脱敏。不能默认把完整提示词发送到 Collector。
价格变更按 request/header 时间选择生效价格。不能用当前价重算过去请求而不标版本。
热重载候选坏候选上下文回滚，旧包继续对外服务。不能先卸旧再试新。
能力缺失强制要求时立即失败，否则显式报告降级。不能把进程隔离叫成强沙箱。
故障演练指定命中次数稳定复现。不能随机污染未指定路径。

关键设计反问

为什么 OTel Logs 不能用于恢复？
它可能采样、脱敏、延迟、乱序或导出失败；这些对观测可接受，对权威状态恢复不可接受。
为什么成本用整数而不是浮点数？
大量小额请求累加会放大二进制浮点误差；高精度整数单位让复算和对账确定。
为什么热重载要先启动候选？
旧包是当前可用服务；只有候选完整通过启动不变量后才能原子替换，否则一次配置错误就会造成停机。
测试全绿是否足以发布？
不够。还需证明构建产物可运行、CLI 协议正确、平台能力满足、故障可收敛且资源无泄漏。

OTel Logs 在 DeepSeek Harness 中的准确角色

原生实现把 canonical Session Event 的投影映射为两个 logger scope：ledger 与 ops。首个 streaming chunk 表示流开始，完整内容最终由 assistant/message 承载；导出前可挂脱敏 waterfall。同步捕获和 exporter 异常都被隔离，不能反向打断 agent loop。批处理、重试、队列和丢失策略归 OTel SDK；handoff cursor 只代表“交给 SDK”，不代表远端已确认。

因此这里采用的是 OTel Logs，而不是用 Trace/Metric 重建 Session。若部署需要 traces/metrics，可为 HTTP、LLM、tool latency 和队列深度另加运维信号，但它们仍不是恢复事实源。

Cost 为什么是投影

  • 同一 turn/step 的最终 usage 覆盖流式中间样本，避免重复计费。
  • 缓存读写 token 与普通 input 分桶，不能重复相加。
  • 按 request/header 的请求时刻选择当时生效价格，而不是按查看账单的今天。
  • 金额使用整数皮美元计算；未知模型进入 unpriced，不静默记为 0。

这个概念的区别：验收证据必须对应待发布版本、部署组合和失败场景；不能用框架具备测试工具替代实际运行结果。
