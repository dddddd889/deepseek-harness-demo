主概念深挖：稳定领域协议

领域协议位于所有模块之间，是模型适配器、Agent Loop、存储、服务端和客户端共同依赖的数据语言。

模型 / 用户 / 工具（上游产生者）
             │ Message、Chunk、Event
             ▼
      领域协议 + 无损 JSON 边界
       ┌──────┼────────┬────────┐
       ▼      ▼        ▼        ▼
 Agent Loop  Session  Server   Web Client（下游消费者）
背景与目的跨边界对象如果各自演化，会出现字段丢失、同名异义和无法重放；稳定协议先固定事实形状，再允许行为独立演进。
输入与输出输入是用户内容、模型增量、工具定义和运行决策；输出是可判别、可序列化、可持久化的消息、流块和会话事件。
适用场景进程内模块调用、HTTP/SSE 传输、JSONL 存储、浏览器投影、版本兼容。
底层组件TypeScript 标签联合、稳定标识、事件映射泛型、JSON 值守卫、快照克隆和深冻结。
核心逻辑先在边界检查值能否被 JSON 无损表达，再克隆冻结；消费者按 type 或 kind 穷尽分派，新增变体会触发编译检查。
权衡严格协议限制任意对象和隐式字段，但换来传输、存储、重放和多语言客户端的一致语义。
方案对比直接共享类实例保留行为却无法跨进程；松散字典灵活但错误延迟到运行时；标签联合在扩展成本和可靠性之间更均衡。

场景穷举

边界数据进入协议
├─ 合法标签变体 → 快照、冻结、传输
├─ 未知标签 → 消费者明确拒绝
├─ NaN / Infinity / undefined → JSON 边界拒绝
├─ 循环引用 → 路径化错误，不进入日志
└─ 新增变体 → 编译期 assertNever 暴露遗漏消费者
场景例子协议行为
正常文本、推理、工具调用、结果和图片在一次消息中混合。通过标签保持顺序和各自字段。
边界空文本、空内容数组、极深 JSON 或大整数。由领域不变量和 JSON 表达能力分别判断。
失败工具参数不是合法 JSON，或值含函数、BigInt。保留原始参数到工具边界；不可表达事件不写入 Session。
演进新增音频内容块或新终止原因。版本化协议并让穷尽分派暴露旧消费者。
误用把类实例、异常对象直接塞进事件。无损 JSON 守卫拒绝隐式丢字段或原型语义。

方案演进能力跨边界能力风险

关键设计反问

为什么工具参数保留原始 JSON 字符串？
模型产生的语法错误本身是需要审计和重放的事实；若领域层提前解析，坏输入会被丢失或改写。
深冻结是不是多余？
TypeScript 的 readonly 只约束编译期；调用方仍可能持有同一对象并在事件写入后修改它。
所有字段都应该进入通用元数据吗？
不应该。高频且影响行为的字段应进入正式协议，只有真正开放、可忽略的数据才适合元数据，否则类型系统无法保护消费者。

为什么工具参数先保留字符串？模型产生的是原始 JSON 字符串。只有 Tool Registry 知道目标 schema，解析、校验和规范化必须留到工具执行阶段；事件账本保留原文才能忠实复盘模型行为。

流式协议：三框架分别怎么做？

同一个问题：半条模型输出如何与完整消息区分？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
LLM StreamChunk 联合类型区分内容增量、usage、finish；循环完成锚点另写 assistant/message。 依据 模型流产生 AIMessageChunk，可累加成完整消息；运行事件流还可包含工具和图状态变化。 依据 LLM 封装提供流式调用能力，Agent 再把解析出的行动或消息放进事件历史；网络 chunk 不等于 Conversation Event。 依据

工具协议：三框架分别怎么做？

JSON 边界：三框架分别怎么做？

同一个问题：跨存储边界能否携带运行时对象？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
Session 校验 JSON 数据并创建脱离、深冻结快照；不能靠 TypeScript readonly 保证持久事实不变。 依据 checkpointer 使用 SerializerProtocol；JsonPlusSerializer 能处理多种类型，不等同于只接受本课 JSON 联合类型。 依据 Event 是不可变 Pydantic 模型，持久事件可通过 model_validate_json 读取；执行器等运行对象不应被当成事件内容。 依据

这个概念的区别：“可序列化”的允许集合不同；协议升级前要验证 round-trip，不是只验证类型检查。

本阶段的调试闸门

  1. 编译期：SessionEventMap 绑定 event type 与 data；新增变体会迫使消费者处理。
  2. 运行期：assertJsonValue() 拒绝 undefined、NaN、BigInt、Date、Symbol 和循环引用。
  3. 身份：Message 在创建时生成 UUID，克隆并深度冻结。
  4. 顺序：Session 独占 seq 分配；恢复日志有缺口立即拒绝。
  5. 往返：事件必须满足 JSON.parse(JSON.stringify(x)) === x。

练习

  1. 给 StreamChunk 新增 image-delta，先运行 typecheck，观察穷尽 switch 报错。
  2. 在一个 Session Event 中放入 new Date()，在 assertJsonValue() 查看失败路径。
  3. 手工把恢复数组的第二条事件 seq 改为 9，确认 Session 拒绝恢复。
