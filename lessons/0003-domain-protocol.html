第 3 课：固定 Agent 领域协议

Agent Loop、持久化、Web Server 和 UI 必须讲同一种语言。本课先固定跨边界数据，再开始写行为。

本课导览

包含内容消息、内容块、模型请求、工具调用、会话事件及无损 JSON 边界。
涉及模块Message、ContentBlock、StreamChunk、Tool、SessionEvent。
白话解释先统一词汇和数据格式，让智能体、服务端、存储和网页端不会各说各话。
解决的问题避免跨模块传输时字段丢失、含义漂移或类型不一致，并为持久化和重放建立稳定契约。

完整能力清单

协议族完整变体保证
消息与来源用户、模型、工具和系统消息；稳定消息标识与来源元数据。创建后与调用方对象隔离。
内容块文本、推理、工具调用、工具结果和图片引用。使用标签联合穷尽处理。
流式协议内容开始、增量、内容结束、用量和终止帧；成功与失败终止原因。提供方差异不穿透运行时。
工具协议名称、说明、参数模式、并行提示、效果声明和结果投影。原始 JSON 参数保留到校验边界。
会话协议请求头、消息、轮次、步骤、工具、权限、压缩与反馈事件。事件类型与数据一一对应。
JSON 边界有限数字、普通对象、数组、循环引用检查、快照和递归冻结。拒绝静默丢失或改变含义的数据。

协议分层

ContentBlock
  ├── text / reasoning
  ├── tool-call
  └── tool-result
        ↓
Message + stable id + source
        ↓
StreamChunk / TokenUsage / FinishReason
        ↓
SessionEvent<type, data>
        ↓
append-only Session
边界必须保留不能进入
模型Message、ToolSchema、StreamChunk工具执行函数、Service 实例
持久化SessionEvent、稳定 id、原始 tool argumentsAbortSignal、Error 实例、闭包
UI/Server事件标签、seq、time、JSON data运行时对象引用
为什么工具参数先保留字符串？模型产生的是原始 JSON 字符串。只有 Tool Registry 知道目标 schema，解析、校验和规范化必须留到工具执行阶段；事件账本保留原文才能忠实复盘模型行为。

本阶段的调试闸门

  1. 编译期：SessionEventMap 绑定 event type 与 data；新增变体会迫使消费者处理。
  2. 运行期：assertJsonValue() 拒绝 undefined、NaN、BigInt、Date、Symbol 和循环引用。
  3. 身份：Message 在创建时生成 UUID，克隆并深度冻结。
  4. 顺序：Session 独占 seq 分配；恢复日志有缺口立即拒绝。
  5. 往返：事件必须满足 JSON.parse(JSON.stringify(x)) === x。

练习

  1. 给 StreamChunk 新增 image-delta，先运行 typecheck，观察穷尽 switch 报错。
  2. 在一个 Session Event 中放入 new Date()，在 assertJsonValue() 查看失败路径。
  3. 手工把恢复数组的第二条事件 seq 改为 9，确认 Session 拒绝恢复。
