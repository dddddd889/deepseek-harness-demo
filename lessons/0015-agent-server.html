第 15 课：Agent Server

Agent Server 位于 Client 与 Agent Runtime 之间：它不是 Agent Loop 的别名，而是网络信任边界、多 Session 路由器、命令控制面和事件数据面。

本课导览

包含内容令牌鉴权、JSON-RPC 命令、多会话路由、SSE 事件流、幂等、背压和优雅停机。
涉及模块AgentServer、RPC 分派器、会话宿主注册表、SSE 连接、HeadlessHost。
白话解释它像智能体运行时的网络前台：先验身份，再把命令送到正确会话，并持续把新事件推给客户端。
解决的问题让远程客户端安全、幂等地控制多个智能体会话，并在断线、慢消费者和服务重启时保持事件连续。

完整能力清单

能力完整行为网络边界
持有者鉴权在任何 RPC 分派、事件读取或附件访问前验证 Bearer 令牌。未授权请求不能探测会话是否存在。
RPC 控制面创建、恢复、发送、运行、取消、快照和关闭会话，返回稳定结果或错误。严格校验请求结构和方法参数。
请求幂等按请求标识缓存同一命令结果，支持客户端安全重试。同一标识绑定不同命令时报冲突。
多会话路由以会话标识定位独立宿主和运行状态，并隔离并发命令。同一会话运行中再次发送被忙碌错误拒绝。
SSE 数据面从指定序号重放历史后追尾实时事件，SSE 事件标识等于 Session 序号。客户端可凭最后序号无缝续传。
资源预算限制 RPC 请求体和 SSE 单帧大小，并处理慢消费者。请求超限返回 413，帧超预算主动断开。
恢复与停机服务关闭时取消运行、关闭连接、刷盘并释放宿主；新服务可冷恢复。网络层不是恢复事实源。
同源网页与附件可挂载静态网页、附件上传和鉴权读取入口。静态路径防逃逸，API 始终保留鉴权。

控制面与数据面分开

接口用途关键语义
POST /rpccreate/resume/send/cancel/snapshot/closeJSON-RPC 2.0、request id 幂等、结构化错误
GET /eventsSession Event replay + tailSSE id=Session seq、Last-Event-ID、队列预算

一次远程 Turn

Client ─ session.send(id=42) ─► Server
Server ─ auth/fingerprint/route ─► active Conversation
Conversation ─ Inbox → Agent.run ─► Session.append(seq=N...)
Session ─ committed event ─► SSE clients
Agent ─ turn/end ─► flush/fsync
Server ─ RPC result ─► Client

重复 id=42 + 相同 params：复用同一 pending/final response
重复 id=42 + 不同 params：IDEMPOTENCY_CONFLICT

恢复在哪里发生

session.resume 通过 HeadlessHost 调用 Session Store：checksum、torn-tail repair、interrupted closer、投影重放，再发布 active Conversation。Agent Server 的幂等缓存、SSE 连接和 live Agent 都是易失控制状态，不是恢复源。

背压与停机

  • SSE 每个连接有独立字节队列；单帧或积压超预算立即断开慢消费者。
  • res.write() 返回 false 时等待 drain/close，不无限写入内存。
  • Server close 先停止接收和关闭 SSE，再取消 running Agent，flush/close conversations，最后 dispose Host。
