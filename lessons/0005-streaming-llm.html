第 5 课：可控流式 LLM 与 DeepSeek Adapter

核心只依赖 StreamChunk 协议。Fake Provider 与真实 DeepSeek Provider 共享同一 Runtime、Assembler 和 Session 落账路径。

本课导览

包含内容模型提供方路由、流式数据块、消息组装、DeepSeek SSE 适配和用量落账。
涉及模块LlmRuntime、LlmProvider、ContentAssembler、DeepSeekProvider。
白话解释无论接假模型还是真实 DeepSeek，都先翻译成同一种小数据块，再由统一流水线拼成回答。
解决的问题隔离不同模型接口和网络协议差异，让流式输出、错误与用量拥有一致且可测试的行为。

完整能力清单

能力正常路径异常路径
提供方注册与路由按提供方标识选择模型实现，并支持运行时撤销。未知提供方转成稳定错误终止帧。
可控假模型脚本化输出文本、工具调用、用量和结束原因，可插入延迟。用于稳定复现取消与竞态。
内容组装按首次索引顺序组装交错文本、推理和工具参数。保留工具参数原始 JSON。
模型步骤落账逐块写入流事件，结束时写最终消息和用量。失败流保留数据块但不伪造助手消息。
DeepSeek 请求适配映射消息、工具、系统提示和模型参数，按次解析密钥。缺少密钥时在网络请求前失败。
DeepSeek SSE 翻译处理跨网络块边界的数据帧、结束标记、工具增量和互斥缓存用量桶。裸异常与取消统一收敛为唯一终止帧。

调用链

GenerateOptions
      │
      ▼
LlmRuntime ── provider route ──> Fake Provider / DeepSeek HTTP SSE
      │                                  │
      │          StreamChunk             │
      ◀──────────────────────────────────┘
      │
      ├── 每帧 append assistant/chunk
      ├── BlockAssembler 组装 content
      └── 成功后 append assistant/message + usage
边界保证调试点
LlmRuntime裸异常、取消都归一为唯一终止 finishLlmRuntime.stream()
BlockAssembler交错 index 仍按首次出现顺序组装BlockAssembler.push()
Model Step先写 raw chunk，再写最终 messagerunModelStep()
DeepSeek Adapter密钥逐请求解析；SSE、usage 和 finish 翻译translateDeepSeek()
密钥不是领域数据。DEEPSEEK_API_KEY 只在发起 HTTP 请求时解析，不能出现在 RequestHeader、Session Event、日志或 OTel 属性里。

故障注入练习

  1. 让 Provider 输出一个 text delta 后抛异常，确认日志保留半截 chunk，但没有伪造 assistant/message。
  2. 把 Scripted Provider 延迟设为 1 秒，10ms 后 abort，观察 aborted finish。
  3. 删掉 SSE 的 [DONE]，确认 Adapter 报协议截断，而不是把半截响应当成功。
  4. 令 prompt_tokens=100、cache hit=40，确认 inputTokens=60，而非重复计为 100。
