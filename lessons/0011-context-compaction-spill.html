第 11 课：Token、Surface、Compaction 与 Spill

长会话治理的核心不是删日志，而是保留事实、缩小模型可见 surface，并把大字节移到受控文件中。

本课导览

包含内容词元计量、上下文压力、模型可见面、摘要压缩、工具结果裁剪和大内容溢出。
涉及模块TokenMeter、上下文投影、Compactor、工具裁剪器、SpillStore。
白话解释完整账本继续保留，只给模型看一份更短的工作摘要；太大的内容移到文件中按需读取。
解决的问题防止长会话超过模型窗口或耗尽内存，同时保留审计、恢复和成本重算所需的原始事实。

完整能力清单

能力具体覆盖不变量
词元估算估算文本、消息及各种内容块大小，单独统计模型可见面。估算值不冒充提供方实际计费。
实际用量累计提供方上报的输入、输出和缓存桶，作为历史用量事实。压缩不能修改历史用量。
上下文压力用最近实际提示词用量作为锚点，再叠加可见面变化预测下一请求。压力值用于窗口决策，不作为新增账单。
压缩区间选择选择已闭合的旧内容，避开仍活跃区域和不可拆分边界。工具调用与对应结果必须作为原子组。
摘要事务先写压缩开始，生成摘要，验证确实变小，再写可见面替换和结束。失败只留闭合审计，不改变模型可见面。
连续再压缩新摘要可替换旧摘要，形成能从事实日志重放的压缩链。原始事件永远保留。
工具结果裁剪模型侧仅保留必要前缀和溢出引用，完整内容交给受控存储。展示截断与数据丢失明确区分。
溢出存储大文本写入随机私有文件，引用保存长度与摘要，读取时校验完整性。引用不能允许路径注入或内容替换。

主概念深挖：事实保留与模型视图压缩

上下文治理的上游是 Session 事实日志和实际用量，下游是下一次模型请求：上游历史保持完整，下游模型只接收预算内的有效视图。

Session events + provider usage（输入）
              │
              ▼
TokenMeter ─► ContextPressure ─► 是否压缩？
                                      │ 是
                                      ▼
Range Selector ─► Summarizer ─► Surface replace（输出）
       │                                  │
       └─ 保证 tool call/result 原子      └─ 下一次 LLM 请求
大工具输出 ─► SpillStore ─► 短引用进入 Surface
背景与目的长会话会同时撞上模型窗口、请求成本和内存上限；直接删历史虽然变短，却破坏恢复和审计。
输入与输出输入是事实事件、模型可见面、实际用量和窗口预算；输出是压力估计、摘要替换事件及大内容引用。
适用场景长时间编码会话、超大测试日志、重复压缩、接近上下文窗口上限时。
底层组件内容估算器、实际用量锚点、可压缩区间选择器、摘要器、事务事件、内容寻址溢出存储。
核心逻辑用最近实际提示词用量校准估算；只选择闭合原子区间；摘要确实更小时才提交 Surface 替换；完整字节仍留在日志或 SpillStore。
权衡摘要降低窗口压力但会损失细节且消耗一次模型调用；保留事实使系统可回溯，却增加本地存储。
方案对比滑动窗口简单但会切断工具因果链；全量摘要容易漂移；事务式区间摘要更复杂，却能保留边界并允许失败回滚。

先拆开四个量

量来源用途是否可计费
累计 TokenUsageSession 中 provider usage 事件历史统计、成本派生可以，但需要带版本的价格表
pressureTokens最近一次 provider prompt usage实测上下文锚点不是新增账单
projectedTokens锚点 + surface 估算变化预测下一请求是否超窗不可以
contextWindow路由模型能力容量分母不可以

更直白地理解

量一句话解释具体例子
累计 TokenUsage这次会话已经实际花掉多少 Token累计输入 8,000、输出 2,000；这是计算实际费用的依据
pressureTokens上一次模型请求实际有多大上次请求输入了 12,000 Token，便以 12,000 作为当前实测起点
projectedTokens预计下一次模型请求会有多大实测起点 12,000，加上新消息和工具结果约 3,000，预计为 15,000
contextWindow模型一次最多能装多少 Token模型上限是 64,000；预计用量接近该值时就应压缩上下文
累计 TokenUsage：已经实际花掉多少
pressureTokens：  上次请求实际有多大
projectedTokens： 预计下次请求会有多大
contextWindow：   模型最多能装多少

projectedTokens 接近或超过 contextWindow
→ 触发摘要、裁剪工具结果或移除旧消息

费用只根据实际 TokenUsage 计算，不能根据预测值计算。
Cost 存哪里？本实验与 DeepSeek Harness 都把原始 usage 放在 Session Event，投影可重建累计桶。货币 cost 应由 provider/model + usage + 生效时间/价格表版本 派生；OTel 可复制指标做观测，但不是恢复或账单事实源。

事实日志与模型 Surface

append user(seq=0) ─┐
append assistant(1) ├─ 原始 Session Event 永久保留
append user(seq=2) ─┘

compaction/start(3)
compaction/summary(4, shadowedTokens)
user summary(seq=5, surfaceOp=replace 0..1)
compaction/end(6)

当前 surface: [5, 2]
原始 log:      [0, 1, 2, 3, 4, 5, 6]

恢复时重放 surfaceOp 即可得到相同模型输入；二次压缩还能替换 seq=5 与后续节点。摘要失败只闭合 start/end 审计 bracket，不产生 replacement。

压缩事务的不变量

  1. 在异步摘要前冻结选区及 token 价格。
  2. 不能切开 assistant tool-call 与对应 tool-result。
  3. 摘要期间选区发生变化则拒绝提交。
  4. 摘要估算 token 必须小于被遮蔽内容。
  5. 先记录 shadow price，再同步提交 replacement。
  6. 任何失败都不改变当前 surface。

超大工具输出与用户附件有什么区别

Spill 就是“超大内容落盘”。当命令输出、测试日志或工具返回文本太大时，系统不会把完整内容一直放在内存、会话日志或模型上下文中，而是把它写入本地受保护文件。模型只看到内容摘要、总字节数、文件引用和分段读取方法，需要时再按范围读取。
工具产生 20 MB 测试日志
  → 完整日志写入本地受保护文件
  → 模型只看到前几行、总大小和文件引用
  → 模型需要更多内容时再分段读取
机制对象模型看到
超大内容落盘（Spill）过大的命令输出、测试日志或工具返回文本内容摘要、总字节数、文件引用和分段读取方法
用户附件（Attachment）用户上传的图片、PDF 等不可变文件附件标识、文件类型、大小等信息

本地超大内容落盘使用会话哈希目录和随机文件名，避免不同会话互相读取或猜测文件路径。目录权限 0700 表示只有当前用户可以访问；文件权限 0600 表示只有当前用户可以读写。实验版还会记录 SHA-256，并在读取时检查文件是否损坏或被修改。

本阶段验收

下面把测试名称中的技术说法和实际验证内容对应起来：

技术说法白话解释
pressure 分桶实际 Token 用量和下一次请求的预计用量分开统计，不会算混。
工具原子边界压缩历史时，工具调用和对应的工具结果必须一起保留，不能只留下其中一半。
replacement 冷重放程序完全重启后，只读取持久化日志也能恢复出压缩后的模型上下文。
链式替换已经生成的旧摘要以后还可以再次压缩成更精简的新摘要。
压缩后压力下降压缩完成后，预计下一次发送给模型的 Token 数确实减少了。
摘要失败拒绝摘要生成失败时，不修改原来的上下文。
摘要不缩小拒绝如果摘要和原文一样大甚至更大，就不采用这个摘要。
spill 路径隔离超大内容按会话分别落盘，一个会话不能读取另一个会话的文件。
篡改检测读取落盘文件时检查校验值，文件损坏或被修改后会被发现并拒绝使用。
