第 2 课：最小可逆插件内核

这一阶段只解决一个问题：能力怎样动态加入 Harness，又怎样在热重载、失败或退出时完整撤销。

本课导览

包含内容服务注册、插件装载、事件订阅、清理栈、失败回滚和卸载。
涉及模块Context、Service、Plugin、Effect、事件总线。
白话解释插件像可插拔电器：插上就获得能力，拔掉时电线、监听器和资源都必须一起收走。
解决的问题防止热重载和启动失败后遗留服务、监听器或进程，为后续能力提供统一生命周期。

完整能力清单

能力具体覆盖边界
服务容器发布、查找和撤销具名服务；拒绝重复服务键。冲突失败时保留原服务。
插件装载插件按顺序启动，并持有独立的子上下文和清理资源。启动失败回滚本插件的部分注册。
事件系统注册、触发并自动撤销随插件生命周期绑定的监听器。卸载后监听器不再接收事件。
副作用清理函数可返回同步或异步清理器，按后进先出顺序释放。一个清理动作不能跳过其余动作。
容器释放逆序卸载全部插件和服务，形成可重复的退出边界。释放后容器回到干净状态。

主概念深挖：可逆插件生命周期

插件内核位于部署装配的下游、所有运行能力的上游；模型、工具、存储和服务端最终都通过同一生命周期加入或退出系统。

Bundle / Host（上游装配）
        │ apply(plugin)
        ▼
HarnessContext ─► PluginContext ─► Service / Event / Effect
        ▲                                │
        └──── dispose / rollback ◄───────┘
                         │
                         ▼
                Agent、工具、存储（下游能力）
背景与目的长时间运行的 Harness 需要动态增加能力，也必须在升级、失败和退出时撤销全部副作用。
输入与输出输入是插件定义和宿主上下文；输出是已发布服务、事件监听器、运行资源及与之配对的清理动作。
适用场景提供方切换、工具包装载、热重载、测试隔离、服务优雅停机。
底层组件服务映射、事件监听集合、插件子上下文、后进先出清理栈和异步释放器。
核心逻辑每次注册立即把逆操作压入插件自己的清理栈；启动失败或卸载时逆序执行，因此部分成功也能回到进入前状态。
权衡显式生命周期增加注册和清理代码，但换来资源所有权清晰、可测试回滚和无闪断热替换基础。
方案对比全局单例使用简单，却难以隔离和撤销；依赖注入容器可解析服务，但若没有 Effect 清理语义仍会泄漏外部资源。

四个最小抽象

抽象职责本课实现
Context服务仓库和事件总线HarnessContext
Plugin一组一起创建、一起销毁的行为Plugin.apply()
Service通过稳定 key 暴露的直接能力provide/get
Effect带清理函数的可逆注册effect/dispose
 
插件挂载
  ├── provide("clock")  ── disposer A
  ├── on("message")     ── disposer B
  └── effect(resource)  ── disposer C

插件卸载
  └── C → B → A（后进先出）
关键不变量：插件启动到一半失败，也必须执行已经登记的 disposer。否则一次 HMR 或配置错误就会留下幽灵 Service、重复 listener 或未关闭资源。

练习：制造一个泄漏

临时删掉 PluginContext.on() 中的 effect() 包装，让监听器直接注册。预测哪个测试失败，再运行测试确认。恢复代码后，回答：

  1. 为什么 Service 方法适合直接调用，而策略拦截更适合 Event？
  2. 为什么 disposer 要做实例身份检查，而不能只按 key 删除？
  3. 为什么卸载顺序必须和注册顺序相反？
