第 13 课：Jobs、子 Agent 与 Workflow

并发不是 Promise.all 本身，而是身份、所有权、取消、资源收敛和可观察生命周期共同组成的控制面。

本课导览

包含内容后台任务、流式输出、任务所有权、子智能体、父子谱系、工作流并发与预算。
涉及模块JobRuntime、SubagentRuntime、子智能体提供方、WorkflowEngine、工作线程。
白话解释把大任务拆给多个工人时，不只要让他们同时开工，还要知道谁负责、怎么取消、何时汇合和如何收尾。
解决的问题控制并发任务的身份、权限、资源和生命周期，避免任务泄漏、结果串线或父任务结束后子任务仍失控运行。

完整能力清单

能力域完整能力收敛规则
后台任务创建分配稳定标识，绑定可选所有者、生产方终止钩子和完成承诺。启动失败不消耗任务标识。
任务输出追加流式文本、单消费游标读取、快照查询和幂等最终输出。监听器异常与任务状态隔离。
任务状态机运行、停止中、完成、已终止和失败；终态由第一次提交决定。终止先通知生产方，再提交停止中。
所有权私有任务只能由所有者查看或操作，无所有者任务可共享。释放所有者时取消、等待并移除全部私有任务。
任务等待支持完成等待、超时和等待者取消。等待超时或取消不等于取消后台任务。
子智能体选择显式或唯一提供方选择，检查可用性、深度、输出模式、工具过滤和角色能力。能力校验在启动发布前完成。
子智能体生命周期开始握手成功后发布开始事件，结束原因规范化并与运行标识唯一配对。启动失败不伪造开始事件，父取消向下传播。
工作流工作线程脚本动态发起子智能体，支持阶段、并发上限、总数上限、扇出扇入和显式结果。超限或脚本失控时取消子任务并在宽限期后强制收敛。

主概念深挖：受控并发编排

并发编排位于父 Agent 或工作流请求的下游、后台生产者和子智能体的上游，负责让并行工作具备身份、所有权和确定收敛。

Parent Agent / Workflow Script（输入）
                │ spawn / agent()
                ▼
        WorkflowEngine（预算、阶段、并发）
                │
                ▼
        SubagentRuntime（能力与深度校验）
                │
                ▼

          ┌─────┼────────┐
          ▼     ▼        ▼
       Child A Child B  Child C
          └─────┴────────┘
                ▼
      汇合结果 + 生命周期事件（输出）
背景与目的Promise.all 只能等待并发承诺，无法回答任务属于谁、怎样读流输出、父任务取消后谁负责收尸。
输入与输出输入是任务启动器、所有者、子智能体请求、工作流脚本和预算；输出是任务快照、流式文本、子结果、工作流结果及生命周期事件。
适用场景后台构建、并行代码调研、父 Agent 委派、扇出扇入工作流和有限资源池。
底层组件任务状态机、单消费游标、完成承诺、终止钩子、子智能体提供方、工作线程消息协议和并发信号量。
核心逻辑先验证能力与预算，再发布稳定运行标识；输出与状态集中进 Job；工作流只通过消息驱动子任务；任何超限或取消都沿所有权树向下收敛。
权衡集中控制面增加状态管理，却换来资源上限、隔离、可观测和确定清理；并发度限制会牺牲峰值速度以保护系统。
方案对比裸 Promise 适合短小同进程工作；作业队列适合持久分布式任务；本实现位于两者之间，专注单宿主可取消 Agent 编排。

三层职责

Workflow Engine（动态脚本、phase、fan-out/fan-in、预算）
      │ agent()
      ▼
Subagent Runtime（provider 选择、能力/深度校验、start/end 配对）
      │ 可选后台化
      ▼
Job Registry（id、owner 鉴权、output cursor、wait/kill、清理）
层拥有不拥有
Job Registry身份、状态、访问、通知进程/Agent 等执行资源
Subagent Runtimeprovider 选择、发布边界、run 生命周期具体模型/进程实现
Workflow Engineworker、脚本预算、child 汇合child Agent 的内部 loop

Job 状态机

start preflight ── run() throws ──► 无记录、id 不消耗
       │
       ▼
    running ── kill() 成功 ──► stopping
       │                         │
       └──────── done ───────────┘
                    ▼
          completed | killed | failed

wait timeout / wait Abort：只离开等待，不取消 Job
owner dispose：cancel → await done → 删除 private record

Job ID 是可预测的 <kind>-N，所以安全边界必须是 owner session 鉴权。unknown 与 foreign 返回相同错误，避免枚举侧信道。

子 Agent 发布边界

  1. 检查 provider 是否存在、可用。
  2. 检查 output schema、深度、工具过滤、persona 是否被 provider 支持。
  3. provider.start() 完成握手并发布 child。
  4. 只有此时才发出 subagent/start。
  5. 任何终态归一为不会 reject 的 result，并发出唯一配对 subagent/end。
  6. dispose() 取消剩余工作并等待资源静止。

Workflow worker

worker: phase()/log()/agent() ── message ──► Host
                                           │ semaphore
                                           │ maxTotalAgents
                                           ▼
                                      Subagent Runtime
                                           │ result/null
worker Promise 恢复 ◄──────── agent-result ┘

脚本运行在独立 Worker Thread，因此死循环不会卡住 Host event loop。Worker 不是安全沙箱；脚本必须来自可信来源。取消先传播给所有 child，并等待 dispose；只有超过 cancelGraceMs 才强制终止。
