第 12 课：Skills、MCP、Web、LSP 与 Attachment

外部能力不是一锅“工具”：统一目录负责发现，各能力 seam 保留自己的选择、生命周期和信任边界，最后只有模型可调用操作桥接进 Tool Registry。

本课导览

包含内容技能发现、MCP 工具桥接、网页搜索与抓取、LSP 语义查询和附件存储。
涉及模块CapabilityCatalog、SkillRegistry、McpBridge、WebRuntime、LspRuntime、附件仓库。
白话解释统一菜单告诉智能体有哪些外部能力，但每种能力仍由自己的适配器和安全规则负责。
解决的问题避免万能接口模糊生命周期和信任边界，并让外部能力可发现、可换代、可恢复且不泄露本地路径。

整体结构

Capability Catalog（摘要/所有权）
 ├─ Skills Registry ─ project/user/bundled roots ─ list → get body
 ├─ MCP Bridge ─ JSON-RPC transport ─ tools/list → Tool Registry → tools/call
 ├─ Web Runtime ─ search/fetch provider selection → web tools
 ├─ LSP Runtime ─ extension route → semantic query provider → lsp tool
 └─ Attachment Store ─ decode/limits/content address → ImageAttachmentRef

为什么不能只有一个万能接口

能力身份关键不变量
Skillkebab-case name摘要发现与正文加载分离；低 rank winner；model/user invocation 分离
MCP Tool(server, rawName)公开名限定 namespace；wire 永远用 rawName；完整分页后原子换代
Webprovider id执行时选择；多候选时拒绝猜测；结果上限由 seam 再执行
LSPprovider id + extension全部扩展原子占用；只暴露语义操作，不暴露任意 JSON-RPC
Attachmentsha256 digest完整解码、类型/字节/像素限制；引用不含路径；冷读复验

MCP 换代时序

tools/list(cursor=∅)
  → tools/list(cursor=next) ...
  → 校验重复 raw/public name 与 cursor loop
  → 构造完整 next generation（此时旧工具仍在线）
  → unregister old
  → register all next
  → 若注册冲突：撤销 partial next，并恢复 old

Attachment 与恢复

Session Event 只持久化 ImageAttachmentRef：attachmentId、真实 media type、字节数和尺寸。恢复后 store 用 digest 定位不可变对象并复验；路径或临时 bearer URL 不进入协议。Fork 继承历史引用，不复制对象。
