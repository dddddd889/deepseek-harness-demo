完整能力清单

能力具体覆盖安全边界
工作区路径解析相对路径，检查现有目标和待创建目标的真实父目录。拒绝绝对路径、上级路径和符号链接逃逸。
文件操作原子写入、有限读取、目录列举、字面字符串搜索和展示裁剪。读取硬上限与展示截断分别报告。
子进程设置参数、工作目录、环境、超时和取消，分别收集标准输出与标准错误。默认清洗密钥、口令、令牌和 DSH_ 环境变量。
进程收敛向进程组发送终止信号，宽限期后升级强制终止，运行时释放时等待全部进程。非零退出是业务结果，不伪装成基础设施异常。
输出溢出内存保留可展示前缀，完整大输出写入私有溢出文件并可回读。输出上限不会导致进程失控或内存无限增长。
终端命令固定工作区和解释器执行命令，返回结构化退出码与输出。命令失败作为结果交还模型。
真实伪终端创建交互终端，支持写入、调整尺寸、读取输出和等待退出。释放运行时时关闭仍存活的终端。

主概念深挖：受控本地执行

本地执行层的上游是工具管线，下游是操作系统文件与进程接口；它把文件、进程、命令和交互终端拆成可限制、可取消、可收敛的独立能力。

Agent Tool（上游）
 ├─ 路径 + 文件参数 ─► WorkspaceFs ─► 文件系统
 └─ command / argv ───► LocalShell ─► ProcessRuntime ─► OS 进程组
                                           ├─ stdout/stderr（输出）
                                           ├─ SpillStore（大输出）
                                           └─ PTY（交互输入输出）
权限与 Sandbox 横切每一次实际访问
背景与目的编码智能体必须接触真实机器，但“万能 shell”会把路径、凭证、进程和输出风险混在一起，难以限制和审计。
输入与输出输入是工作区相对路径、命令、参数、环境、终端输入和取消信号；输出是文件内容、搜索结果、退出码、标准流和溢出引用。
适用场景阅读和修改代码、运行测试、启动开发服务、操作交互式命令行。
底层组件realpath 与符号链接检查、原子重命名、Bun.spawn、独立进程组、信号升级、内存输出预算和原生 PTY。
核心逻辑文件访问先解析真实边界；子进程先净化环境再创建进程组；取消先温和终止、超时后强制终止；大输出仅把前缀留在内存。
权衡拆层增加接口数量，却使路径安全、进程生命周期和交互终端能分别测试和替换。
方案对比直接调用系统 shell 最灵活但参数和边界不透明；结构化进程接口更安全，确需 shell 语义时再通过 LocalShell 显式进入。

场景穷举

本地操作
├─ 工作区内正常文件 → 读/写/列举/搜索
├─ ../、绝对路径、符号链接 → 拒绝逃逸
├─ 小输出进程 → 内存返回
├─ 大输出进程 → 前缀 + SpillRef
├─ 超时/取消 → SIGTERM → 宽限 → SIGKILL
├─ 非零退出 → 结构化业务结果
└─ 交互程序 → PTY write/resize/read/exit
场景关键风险控制措施
新建文件目标不存在，无法 realpath 自身。逐级寻找真实父目录并确认仍在工作区。
符号链接字符串路径在根内，真实目标在根外。读取目标和写入父目录都检查 realpath。
凭证环境子进程继承 API_KEY/TOKEN。默认清洗敏感名称，只允许显式覆盖。
进程树只杀父进程，孙进程继续存活。POSIX 使用独立进程组并向组发信号。
输出洪泛无限 stdout 耗尽内存。内存预算后溢出磁盘，保留完整内容摘要。
平台差异PTY、信号或沙箱不可用。运行能力探测，明确失败或声明降级。

多方案对比

方案灵活性安全边界选择条件
直接 shell 字符串最高。参数、引用和副作用不透明。用户明确提供的复杂 shell 语义。
结构化 argv 子进程高。无 shell 注入，环境和 cwd 明确。框架内部启动工具。
容器/虚拟机执行中。隔离最强。不可信代码、多租户、跨平台一致性要求高。
宿主 OS 沙箱高。依赖平台能力。本地编码助手，需要访问真实工作区。

关键设计反问

路径前缀检查为什么不够？
符号链接能让字符串仍以工作区开头但实际解析到外部；安全判断必须基于规范化真实路径。
非零退出为什么不是异常？
测试失败、grep 未命中都用退出码表达正常业务结果；抛异常会丢失 stdout/stderr 和可修正上下文。
为什么既需要 Shell 又需要 ProcessRuntime？
Shell 负责命令语言，ProcessRuntime 负责生命周期和字节流；分开后无 shell 的结构化程序也能复用安全收敛能力。

终端命令：三框架分别怎么做？

同一个问题：连续两次命令之间会保留 cd 和 shell 变量吗？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
bash-local 每次启动新的非登录 bash -c，不保留 shell 状态；超时与上游取消分别报告 timedOut 和 aborted。持久终端由另一个提供方负责。 依据 LocalShellBackend 的 execute 使用宿主 shell 执行，以 root_dir 为工作目录；该接口不等于持久交互终端。 依据 TerminalTool 面向持久会话，支持 tmux、subprocess 或 PowerShell 后端；不要将它与 Workspace 单次命令接口混同。 依据

这个概念的区别：测试连续 cd/export 时，先确定比较的是单次执行接口还是有状态终端。

真实伪终端：三框架分别怎么做？

同一个问题：交互命令等待输入时，谁判定就绪并发送中断？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
terminal-bash 消费 spawnTerminal：进程提供方分配 PTY，终端后端结合提示符和前台状态判定就绪；取消发送真正 SIGINT，不用写入控制字符模拟。 依据 LocalShellBackend 的执行接口不是 PTY 协议；交互终端需由所选沙箱/自定义工具另外提供，不能从 execute 推导 resize、前台进程组等能力。 依据 TerminalTool 自动选择平台后端，Unix 优先 tmux、否则 subprocess，Windows 用 PowerShell；“终端工具”并不保证所有后端均为同一种 PTY 实现。 依据

这个概念的区别：持久状态、终端仿真和伪终端是不同能力，平台回退时要逐项验证交互行为。

文件安全

用户路径
  → 拒绝绝对路径
  → resolve(root, relative)
  → 拒绝词法 .. 逃逸
  → realpath(existing / nearest ancestor)
  → 再次拒绝 symlink 逃逸
  → 执行读写
只检查字符串前缀不够。workspace/escape -> /outside 看起来位于 root 下，真正访问时却已越界，所以现有路径和可写父目录都必须检查 realpath。

工作区路径：三框架分别怎么做？

同一个问题：配置 cwd 后，文件工具还能访问根目录之外吗？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
fs-local 的 cwd 只是相对路径基准，绝对路径和 .. 可越出；realpath 用于目标身份。需要写入围栏时另装 fs-sandbox，不能把本课 WorkspaceFs 的限制当作上游默认。 依据 FilesystemBackend 需 root_dir 配合 virtual_mode 才启用路径限制；启用 shell 后，该限制不能防止命令访问其他路径。 依据 Workspace 设定本地或远程执行位置；LocalWorkspace 可访问宿主，目录本身不等于文件访问隔离。 依据

这个概念的区别：工作目录回答“相对路径从哪里算”，访问围栏回答“允许到哪里”，两者必须分开配置。

文件操作：三框架分别怎么做？

同一个问题：一次编辑的存储语义和模型展示由谁负责？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
fs-local 提供原子 writeText、目标锁内 editText 和可选版本防护；流式读取与工具行窗口分层，搜索不是这个本地存储提供方的职责。 依据 内置读写编辑和搜索工具通过 Backend 操作；StateBackend 写图状态，FilesystemBackend 写真实文件，换后端会改变持久化位置。 依据 Workspace 提供文件上传下载；模型编辑工具则由 ToolDefinition/Executor 实现。不能用上传成功推断编辑工具具备原子替换和版本校验。 依据

这个概念的区别：对比文件能力要落到实际操作与后端，不能从“都有文件工具”推导相同并发写入保证。

进程生命周期

spawn detached process group
  ├── stdout/stderr → 有限内存前缀 + 完整 spill
  ├── abort/timeout → SIGTERM
  ├── grace 到期    → SIGKILL
  └── runtime dispose → 终止并等待所有后台进程和 PTY

父进程环境会默认删除名字匹配 KEY|PASSWORD|SECRET|TOKEN 以及 DSH_* 的变量。只有调用方显式传入的环境项才可以恢复它们。

子进程：三框架分别怎么做？

同一个问题：命令以谁的环境和权限启动？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
subprocess-local 清洗形似凭据及 DSH_* 的继承变量，再合并显式 env；普通进程以显式 stdio 启动，底层不负责解释 shell 命令。 依据 LocalShellBackend 在宿主用 subprocess.run(shell=True) 执行，提供 env/inherit_env、超时和输出预算，没有内置隔离。 依据 LocalWorkspace 直接启动子进程；RemoteWorkspace 经 HTTP 委托 Agent Server，实际进程在远端环境中。 依据

这个概念的区别：环境继承、shell 解释和执行位置是三个独立问题；远程执行也需要检查远端凭据与权限。

进程收敛：三框架分别怎么做？

同一个问题：工具返回取消后，后代进程一定都停止了吗？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
terminate 先 TERM 再 KILL，waitForExit 等待受管进程树，dispose 终止并等待；守护化逃逸与 Windows 尽力而为清理仍是明确边界。 依据 LocalShellBackend 的 timeout 是命令预算；公开后端说明未承诺与 DeepSeek 相同的整棵进程树等待协议，不能据超时字段断言后代已回收。 依据 Workspace 上下文退出用于资源管理；LocalWorkspace 保留本地资源，远程实现可停止容器。它与逐命令进程树确认是不同生命周期。 依据

这个概念的区别：验收应观察后代是否存活，而不只是等待 API 返回；资源拥有者与终止范围必须明确。

输出溢出：三框架分别怎么做？

同一个问题：模型只看到截断输出时，完整内容还能找回来吗？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
收集模式保留内存尾部，可选 spill 保存完整流；超过 spill 总上限会丢弃不完整文件，仅返回截断尾部。完成文件留在临时目录供外部清理。 依据 大工具结果可卸载到 Backend 后按文件读取；若下层执行后端已经截断，后续卸载不能找回被丢弃字节。 依据 TerminalObservation 渲染使用 maybe_truncate，并传入 full_output_save_dir 保存输出；这是终端结果展示层机制，不等于底层进程采集无损无上限。 依据

这个概念的区别：区分采集上限、落盘上限与模型展示上限；“有文件引用”必须同时说明文件是否完整。
