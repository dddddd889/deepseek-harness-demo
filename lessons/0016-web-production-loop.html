主概念深挖：可恢复客户端投影

Web Client 位于 Agent Server 的下游、用户交互的上游；它不是事实拥有者，而是 Session 事件在浏览器中的可丢弃读模型。

用户操作（发送、取消、审批、上传）
        │ RPC / HTTP（输入）
        ▼
Agent Server ─► Session Log
        │ snapshot(events[0..N])
        ├────────────────────► ClientProjection.reset
        │ SSE(after=N)                   │
        └────────────────────► apply(event)
                                         ▼
                                消息、状态、用量 UI（输出）
断线：丢弃连接，不丢 Session；以 lastSeq 重新追尾
背景与目的浏览器随时刷新、休眠或断网，本地状态不能承担恢复责任；同时用户需要实时看到模型、工具和审批进度。
输入与输出输入是权威事件快照、SSE 增量和用户命令；输出是可渲染会话视图、RPC 请求、审批决定和附件引用消息。
适用场景实时聊天界面、长任务进度、跨刷新恢复、多客户端审批和图片输入。
底层组件AgentClient、ClientProjection、fetch RPC、EventSource/SSE、InteractionBroker、附件上传接口和 CSP。
核心逻辑先用快照建立完整前缀，再以最后序号追尾；重复事件忽略，缺口立即失败并重新取快照；写命令不直接修改视图，等待权威事件回流。
权衡事件驱动 UI 存在短暂命令到视图延迟，却避免乐观状态与服务端事实冲突；全量快照简单但大历史成本会增长。
方案对比本地状态持久化启动快但容易陈旧；服务端渲染一致性高但不适合高频流；快照+增量投影兼顾恢复和实时性。

场景穷举

浏览器生命周期
├─ 首次打开 → snapshot 0..N → SSE after=N
├─ 重复 SSE event → 幂等忽略
├─ seq 缺口 → 停止应用 → 重新 snapshot
├─ 刷新/休眠/断网 → 本地状态可丢 → 按 lastSeq 恢复
├─ 多客户端审批 → 首个有效决定胜出
├─ 图片上传 → 验证/持久化 → 引用消息
├─ 静态路径逃逸 → 拒绝
└─ RPC 未授权 → 不因同源而豁免
场景客户端动作权威来源
正常追尾增量 apply 事件。Agent Server 的 Session 事件。
命令等待显示请求进行中，但不伪造最终消息。事件回流后更新视图。
乐观审批冲突第二客户端收到已决定结果。InteractionBroker 首写。

缓存陈旧丢弃本地缓存并取新快照。浏览器永不覆盖服务端事实。

关键设计反问

为什么命令成功后不直接修改消息列表？
RPC 响应只证明命令处理结果，不一定包含完整事件顺序；等待权威事件可让所有客户端得到同一状态。
重复事件和序号缺口为什么处理不同？
重复可由重连自然产生且安全忽略；缺口意味着因果事实缺失，继续投影会得到错误状态。
同源网页为什么仍需要 Bearer？
同源限制浏览器来源，不等于确认使用者身份；本地恶意页面、泄露地址或跨进程调用仍需令牌边界。

附件闭环：三框架分别怎么做？

同一个问题：图片被消息引用后，刷新和恢复还能读取吗？

DeepSeek Harness 原实现LangChain DeepAgentsOpenHands SDK
attachment-local 用 sha256 不透明 id 指向持久对象，日志只存引用和校验元数据；读取重新验证摘要，历史图片不因后来收紧准入限制而失效。 依据 消息模型支持多模态内容，但消息中的图片块与应用上传对象生命周期是两层；应用需保证引用在恢复时仍可访问。 依据 Workspace 提供上传下载接口，本地复制或远程传输文件；上传到工作区与消息图片引用不是同一个持久对象协议。 依据

这个概念的区别：上传成功、模型收到图片和长期可恢复要分别验证，不能用其中一个替代整个附件闭环。

Web 安全边界

  • Token 只放 Authorization header 和 sessionStorage，不进入 URL。
  • SSE 使用 fetch stream，因此能携带 Bearer header；不使用受限的原生 EventSource。
  • 静态路径 realpath containment，拒绝 dot segment/symlink 逃逸。
  • CSP、nosniff、no-referrer、frame-ancestors 防御默认开启。
  • 附件读取同样要求鉴权，durable ref 不是公开 bearer URL。
