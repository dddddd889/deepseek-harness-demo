第 6 课：Inbox 驱动的 Agent Loop

把用户输入、Session、LLM 串成一个不可重入的 turn/step 状态机，并让取消和错误也闭合日志。

本课导览

包含内容收件箱、轮次、步骤、模型调用、停止原因、并发保护和取消。
涉及模块HarnessAgent、Inbox、Turn、Step、LlmRuntime、Session。
白话解释智能体像一次只处理一张工单的工作人员：领取消息、调用模型、记录结果，然后完整收尾。
解决的问题防止同一智能体重复运行和事件交叉，并保证成功、错误、取消都留下可恢复的闭合日志。

完整能力清单

能力行为不变量
消息入箱接收用户消息并写入会话，等待下一轮原子认领。运行中到达的新消息留给下一轮。
单轮运行从空闲进入运行，生成轮次与步骤标识，调用模型并闭合事件。同一智能体不可重入。
步骤推进一个轮次内可按模型结果推进多个步骤。步骤编号连续且属于当前轮次。
停止原因区分完成、工具阻塞、最大步骤、取消和错误。所有出口都写入轮次结束事件。
取消传播中止当前模型或工具工作并等待协作式收尾。生命周期投影仍然闭合。
空运行没有待处理输入时直接返回。不产生任何副作用或伪事件。

主概念深挖：Agent Loop 状态机

Agent Loop 位于用户/服务端命令的下游，模型与工具运行时的上游，并用 Session 事件把每次决策变成可恢复事实。

User / Server ── send(Message) ─► Inbox
                                  │ run 原子认领
                                  ▼
                         Turn ─► Step ─► LLM
                                  ▲        │
                                  │   Tool calls
                                  └── Tool results
                                      │
                          Session events + TurnResult（输出）
背景与目的“调用一次模型”不等于智能体；智能体还要管理输入归属、多步骤推进、并发、取消和所有终止出口。
输入与输出输入是收件箱消息、Agent 配置和取消信号；输出是轮次结果，以及完整的轮次、步骤、消息、工具和错误事件。
适用场景单会话问答、连续工具调用、远程取消、并发请求保护和崩溃后继续编号。
底层组件空闲/运行状态、收件箱队列、轮次与步骤计数器、模型步骤、工具执行器和 AbortController。
核心逻辑run 先原子切换状态并认领当前输入，随后循环执行模型步骤；有工具则执行并继续，无工具或达到边界则按明确原因闭合。
权衡每个 Agent 串行运行限制单会话吞吐，却避免事件交错和上下文竞态；跨任务并行交给后续子智能体层。
方案对比递归函数写法简短但难统一取消和步数限制；显式状态机代码稍多，却能穷尽正常、错误、阻塞和取消路径。

必须验证的竞态

  1. 同一 Agent 并发 run() 必须拒绝，不能产生交错 seq。
  2. 运行期间新到的输入不能混进已认领 turn，必须留给下一 turn。
  3. 取消慢流后仍产生 step/end 与 turn/end。
  4. 恢复已有 Session 后，下一个 turn 编号不能从 1 重来。
