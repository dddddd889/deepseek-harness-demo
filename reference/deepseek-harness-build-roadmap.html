1. 前端与客户端

内部关系：模块加载装配插件；运行时接收连接事件；React 将状态与插槽贡献渲染为业务界面。

子系统分支职责与边界实现依据
应用外壳与插件装配外壳启动客户端 Cordis；modules 加载插件，HMR 负责卸载与重载。插件热更新不是会话事件推送。modules/README.zh.md
通信与连接生命周期connection 管理连接代次和握手；业务调用走 HTTP，下行使用 events.mux 与 events.host 两条 WebSocket。connection/README.zh.md
会话与工作区状态SessionRuntime 和 WorkspaceRuntime 管理客户端对象、列表及事件镜像；历史分页和 ProjectionValueStore 不等于持久化数据库。runtime/README.zh.md
UI 扩展与 React 渲染ui-slots 声明 UI 扩展约定；运行时提供状态源，web-react 绑定订阅与渲染。组件不是通信层。ui-slots/README.zh.md
对话与任务界面业务插件呈现对话、工具结果、待审批或待回答操作，以及子智能体、Jobs、Workflow 状态；实际执行仍在服务端。ui-conversation/README.zh.md
工作台与偏好界面侧栏和工作区组织会话；模型选择、设置、主题与语言由相应插件贡献。设置界面不持有提供方执行能力。ui-settings/README.zh.md

2. 后端：服务接入层（Agent Server 职责）

内部关系：浏览器 → HTTP / WebSocket 载体 → 协议与对象解析 → 业务服务；推送反向送回客户端。

子系统分支职责与边界实现依据
Web 宿主与资源服务Web 宿主提供 HTTP 服务、前端静态资源和插件资源；原实现不是一个包办一切的 AgentServer 类。webserver/README.zh.md
远程调用网关Gateway 暴露显式声明的 Remote 方法，将 wire identity 解析为 Host 对象或作用域，再调用拥有该能力的服务。docs/api-gateway.zh.md
会话操作与历史入口接入层把会话操作交给运行时或查询服务；history 可能恢复尚未附加的会话，不能假定它永远只读数据库。connection/README.zh.md
实时事件下行events.mux 与 events.host 分别传递对应的服务端帧；浏览器不在这些 WebSocket 上发送业务请求。connection/README.zh.md
访问与协议边界Web 载体的浏览器访问限制不是完整认证系统；远程方法声明和对象解析也不能替代部署层安全设计。connection/README.zh.md
无界面与 SDK 入口Headless 使用同一核心能力建立持久 Agent，但不需要经过 Web 接入层。SDK 入口与浏览器产品载体不混为一谈。headless/README.zh.md

3. 后端：智能体核心与编排

内部关系：输入进入 Inbox → Turn / Step 推进 → 上下文与模型 / 工具交互 → Session 记事实 → 投影消费。

子系统分支职责与边界实现依据
智能体与运行生命周期Agent 接口与注册表提供运行对象；agent-loop 是具体驱动器。恢复入口调用持久化服务，而不是从观测平台重建。agent-loop/README.zh.md
循环与输入调度Loop 领取输入、推进模型与工具步骤并处理停止；Turn 与 Step 是持久事件边界，不只是界面上的一条消息。agent-loop/README.zh.md
会话事实与读模型Session 保存有序事实；模型历史与客户端读模型分别派生。消息呈现、原始事件、统计投影不是同一种数据。session/README.zh.md
上下文工程系统提示词与工具 schema 组装后参与请求；Token 测量、Compaction 和结果修剪控制上下文，外置产物由存储能力承接。docs/capability-seams.zh.md
子智能体与后台任务subagents 提供创建与继续接口；Jobs 登记后台工作。两者的对象和生命周期不同，不统一简化为一次工具调用。docs/capability-seams.zh.md
工作流与目标控制工作流引擎负责脚本编排；目标、计划、用户问题等插件参与运行控制。具体能力是否启用取决于装配。docs/capability-seams.zh.md

4. 模型、工具与执行环境

内部关系：Loop 调模型或工具；工具经审批 / 策略约束后调用能力后端；结果返回 Session 与下一步上下文。

子系统分支职责与边界实现依据
模型适配与流式协议LLM 服务注册适配器，固定单次调用配置；分片、完成与用量按协议返回。模型选择界面不直接执行提供方请求。llm/README.zh.md
工具注册与执行管线ToolRuntime 统一注册和执行；pre-execute、guard、execute、post-execute 等阶段分离策略和能力实现。tools/README.zh.md
审批、权限与隔离approval 等待用户决策，sandboxPolicy 表达策略，sandbox 约束进程。用户点击允许不意味着跳过全部执行限制。docs/capability-seams.zh.md
本地与远程执行后端文件系统、进程和终端各有服务边界，可选择本地或隔离环境实现；工作目录内容与会话记录独立存在。docs/capability-seams.zh.md
外部工具与知识接入MCP 接入工具，Skills 提供技能内容，Web 与 LSP 有各自服务接口；它们不是同一个网络调用层。docs/capability-seams.zh.md
结果与大内容处理执行结果可携带附件或外置引用；保留、修剪和存储职责分离。重放引用不会自动重新执行工具来补内容。docs/capability-seams.zh.md

5. 数据库与持久化

内部关系：Session → 持久化接口 → SQLite 或 JSONL；查询索引从事实派生，资源内容和非会话数据另行保存。

子系统分支职责与边界实现依据
会话持久化接口SessionPersistence 定义追加、加载、列举和持久化屏障；逻辑事实约定独立于物理格式。session-persistence/README.zh.md
权威存储后端SQLite 将头与事件存入 sessions / events 表，以事务提交；JSONL 是另一种实现。默认选择 JSONL 不代表 SQLite 只能做缓存。session-persistence-sqlite/README.zh.md
恢复、修复与分叉恢复从配置的后端读取，并处理崩溃留下的轮次；Fork 保留谱系与继承边界。未知工具结果不应盲目重试。session-persistence/README.zh.md
派生查询与搜索session-query-sqlite 管理派生索引，不承担权威持久化；不能指向会话存储数据库，默认组合不启用内容搜索。session-query-sqlite/README.zh.md
非会话数据与配置ctx.storage 路由非会话领域 KV 的 JSON / SQLite 后端；settings 与 credentials 是另外的服务边界，不能把所有配置都说成存入事件表。docs/capability-seams.zh.md
附件与溢出产物attachments 与 spillStore 管理实际内容；事件记录引用。备份和恢复需覆盖被引用产物，不只是 events 表。docs/capability-seams.zh.md

6. OTel 与可观测性

内部关系：捕获 → 投影与脱敏 → OTel Logs SDK → OTLP 接收端；用量统计是另一条读模型分支。

子系统分支职责与边界实现依据
事件与运维信号捕获遥测协调器捕获会话事实副本和运维记录；实时跟随或按需回放由后端模式决定，不改变原始会话事实。session-telemetry/README.zh.md
投影、脱敏与分享策略默认 DISABLED；FULL 全量跟随，FEEDBACK_ONLY 按已记录反馈触发。脱敏是扩展点，默认没有规则，部署方须自行配置。session-telemetry-otel/README.zh.md
OTel Logs 导出管线记录交给 OTel SDK 的日志管线，经 OTLP/HTTP 导出；排队、重试及丢失策略属于 SDK。不是把恢复记录直接搬进 Trace。session-telemetry-otel/README.zh.md
接收与观测存储接收端由部署方配置，不能假定已部署某个 Collector 或数据库；观测副本可能缺失，不是会话恢复依据。session-telemetry-otel/README.zh.md
用量、成本与统计读模型用量等原始字段随事件保存，相应消费者计算展示值；sessionStats 提供轮步与时延统计，不应称为完整财务结算账本。session-stats/README.zh.md
运行时诊断与不变量invariants 提供包拥有的不变量注册，帮助定位运行时违约；测试与发布检查属于工程底座，不归 OTel 导出器负责。invariants/README.zh.md

会话头、原始事件SessionPersistence：SQLite 的 sessions / events 表，或 JSONL 后端；默认组合选择 JSONL，不表示数据库不受支持。是，恢复读取已配置后端；活动会话先在内存推进，flush 是持久化屏障。
会话搜索索引session-query-sqlite 的独立派生数据库；默认组合 openAt: never，不启用内容搜索。否，可重建，不能与权威持久化数据库共用路径。
非会话领域数据ctx.storage 与领域路由选择的 JSON / SQLite KV 后端。不是会话事件恢复来源；其自身数据需要相应的持久化与备份。
附件、溢出内容对应能力的存储后端；事件保留引用。完整取回内容还依赖引用指向的产物，不能只备份事件。
用量、成本与统计事件携带的相关原始字段随会话后端保存，汇总由相应投影或消费者计算；独立计费账本是另一个需求。可从已记录字段重算，不假定每个提供方都有完整价格或成本字段。
观测记录OTel SDK 队列 → 配置的 OTLP 接收端 → 部署方观测存储；具体存储产品未固定。否；可能禁用、延迟或丢失，不用它替代持久化。

把各层放进一次真实操作

正常对话：网页提交输入 → 接入层调用智能体 → Loop 请求模型、经权限检查执行工具 → Session 追加事件 → 客户端收到投影更新；持久化按批次写入，遥测在启用时走独立导出链路。

重启恢复：后端从配置的 SessionPersistence 加载会话头和事件，处理被中断的轮次并重建投影；不会从 OTel 接收端或搜索索引恢复。使用 SQLite 时，这条路径直接读数据库，不需要先找 JSONL。

边界情况：浏览器断线不等于后端任务已经停止；恢复未确认的有副作用工具调用不能盲目重试。OTel 默认 DISABLED，FULL 与 FEEDBACK_ONLY 的导出时机也不同。Headless 装配无需 Web 服务接入层。

原实现依据：核心与装配 · 持久化接口 · SQLite 权威存储 · 查询索引 · 非会话存储 · OTel Logs。
