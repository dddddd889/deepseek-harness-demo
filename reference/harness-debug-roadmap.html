DeepSeek Harness 逐步实现与调试路线

47 个主步骤覆盖 115 个功能项；40～46 为新增 Electron 桌面分支，旧编号保持不变。每步先用固定样本跑通，再接真实模型或环境；大步骤内按功能项逐个增加样本，保留此前步骤可独立运行。

第一目标：步骤 00～09 完成“输入 → 模型流 → 工具 → 下一次模型请求 → 答案 → 取消”。步骤 10 加真实文件，就能做“读取 README 并解释启动方法”。全量功能不必都做完才能使用。

每一步怎么调试

第一次使用先看 第 00 步新手操作说明。在本机编辑器创建文件，在终端运行命令。

  1. 新建独立实现项目，或复制 harness-from-zero/ 到任意新目录；源码与测试目录当前为空。启动方法见 空项目说明。
  2. 按卡片自己创建本步文件和测试；所列命令要在实现后执行，不能把计划文件当成已有代码。
  3. 在自己的代码中沿“输入 → 状态变化 → 事件 → 结果”设断点，保存输出。
  4. 用固定分片、可控制 Promise 和临时文件稳定复现异常，修正后回归此前测试。
  5. 留下解释、运行产物和故障记录，再进入下一步。只有卡住时按需展开教学参考。

主执行目录：harness-from-zero/，不导入已有实验室。Bun、Host、Web、ACP 与 Electron 全部在本机启动和调试；Compose 只提供按需外部资源。步骤 00 先自己创建 src/main.ts，运行 bun run dev，再新增首个测试和执行 bun run build。

假模型固定返回分片、工具调用或错误；真实 API 另行显式开启，不混入离线验收。多平台沙箱、PTY、真实 MCP / LSP、浏览器交互和进程外协议都需要各自的集成证据。

用读取 README 的任务串起来

固定假模型第一步返回 read 工具调用，参数指向临时工作区的 README；工具返回已知文字，假模型第二步返回包含该文字的解释。先确认每步日志和第二次请求内容，再切换真实模型。

依次在 HarnessAgent.run、model-step.ts、ToolRegistry.prepare、ToolRegistry.execute、Session.append 设断点。观察同一会话内 Turn 不变、Step 递增，工具 callId 和结果配对；第二次请求必须包含工具结果。

然后分别把模型流、工具和审批响应卡在可控 Promise 上，取消后释放 Promise。验收最终只有一个轮次结束、迟到批准不执行工具、后续输入仍能运行。参考 工具循环与取消测试、审批竞争测试；这是组合验收场景，不是声称现有 HeadlessHost 已默认装好读文件工具。

先做出可用版本的短路线

带恢复的 CLI：00～14 → 24。教学 Web：00～17 → 24～27。文本 ACP：00～14 → 24 → 28；图片支持另补 15～17。Electron 桌面：00～17 → 24～27 → 40～46。桌面编号追加，但可在 Web 之后直接进入；桌面开发在宿主机进行，说明见 桌面从零任务书。MCP、Job、子 Agent 和工作流不是接入 Web、ACP 或桌面的前置条件，18～23 可以后补。

编号给出建议阅读顺序，卡片的“前置”才是依赖要求；观测、真实隔离与 Hook 也可在其前置完成后提前加入。

四条跨层链路最终怎么验收

链路观察和复现通过条件
Prompt接收确认之后暂停执行，继续发送或取消；观察同会话排队、多会话隔离。接收与执行终态分别可见；ACP 等待语义与 Web 接收确认分别正确。
输出文本输出到一半断流，重试或断连重连。临时分片与已提交消息不混淆；重复事件不重复渲染，缺口能恢复。当前原版 ACP 只转发已提交输出，不宣称有 token 级推送。
取消分别卡住模型、工具、审批和输入 admission，再取消。本轮终态唯一，待处理输入遵循入口策略，迟到结果不启动下一步，资源收敛；已发生的副作用另行说明。
审批两个客户端同时回答、取消后迟到批准、审批期间断开连接。唯一有效决定；未获授权不执行；同意后工具最多执行一次。

查看原版 Web 与 ACP 的 API、调用方向和源码位置。共用运行时实现不意味着共享会话实例，也不意味着两种接入有相同的产品语义。
