## 什么时候会用到这一页

别的Bun程序想使用自己的Harness，不需要导入整个Agent内部。SDK负责启动隔离运行时，通过协议创建会话、接收通知、等待完成和回收进程。

### 这次数据怎么走

```text
HarnessSDK spawn sdk-server → stdio Peer/framing → remote绑定Host → create → run中watch/submit/wait/read → 返回ending/events/text → stdin.end使服务端清理并退出
```

### 对应时序图

从上往下读；实线箭头表示调用或发送，虚线箭头表示返回或事件通知。`opt`表示可选操作，`alt`表示不同结果，`loop`表示重复，`par`及其`and`分支表示并行；“未接入”及fixture说明按图中标注理解。

```mermaid
sequenceDiagram
    participant C as SDK 调用方
    participant S as HarnessSDK（调用方进程）
    participant R as sdk-server 的 Peer 与 remote（Bun 子进程）
    participant H as 子进程 Host 与 Agent
    C->>S: new HarnessSDK(home, cwd)
    S->>R: spawn Bun，stdio 接 Peer 与 framing
    R->>H: 创建 Host，绑定 remote
    C->>S: create()
    S->>R: session.create
    R->>H: host.create
    H-->>R: header
    R-->>S: session.create 响应
    S-->>C: header
    C->>S: run(id, content, onEvent)
    S->>R: session.watch
    R->>H: 校验 owner，订阅并读取历史
    H-->>R: 历史事件
    R-->>S: watch 快照
    S->>R: session.submit
    R->>H: 校验 owner，agent.submit
    H-->>R: inputId
    R-->>S: submit 响应
    S->>R: session.wait
    R->>H: 校验 owner，await agent.idle

        H-->>R: event
        R-->>S: session.event 通知

    end
    H-->>R: idle 后最后 turn/end
    R-->>S: wait 响应
    S->>R: session.read
    R->>H: 校验 owner，session.read
    H-->>R: 全量会话事件
    R-->>S: read 响应
    S-->>C: ending、events、text
    C->>S: close()
    S->>R: stdin.end 发送 EOF
    R->>H: host.close
    H-->>R: Host 清理完成
    R-->>S: 子进程退出
```

### 到底谁启动了谁

```text
你执行 bun src/sdk-demo.mjs                    ← 父进程，打印上面的演示结果
  → new HarnessSDK(...)
    → spawn Bun src/sdk-server.mjs              ← SDK 自动启动子进程
      → new Host(home, modelFactory)             ← 子进程持有 Host
      → remote(peer, host, 'local')              ← 复用 043 的领域控制器
  → create() → run(...) → close()
    → stdin.end() → 子进程关闭 Host 并退出
```

标题中的“同一个 Host”是 SDK、其他接入方式复用同一套 Host 与 Agent 实现。本章 SDK 每次构造时新启动一个 Host 子进程，不会自动连接第 041 课另一次运行的 Host。一次 SDK 存活期间，多个 `create()` 共用它的这个子进程。

不要把 `bun src/sdk-server.mjs` 当作本章演示命令：它是 SDK 管理的服务端入口，需要 `HARNESS_HOME` 和 stdin 上的协议请求，stdout 只输出协议数据。也不要用 `bun src/main.mjs` 验收本章，那是原来的 CLI。

### 创建 [`src/sdk-demo.mjs`](../../../harness-own/src/sdk-demo.mjs)

````javascript
import assert from 'node:assert/strict'
import { mkdirSync, mkdtempSync } from 'node:fs'
import { resolve, join } from 'node:path'
import { HarnessSDK } from './sdk.mjs'

// 每次演示使用独立目录；退出后保留日志，方便查看 Host 实际保存的事件。
const temporaryRoot = resolve('tmp')
mkdirSync(temporaryRoot, { recursive: true })
const home = mkdtempSync(join(temporaryRoot, 'sdk-044-'))

// 演示固定走离线模型，避免当前终端的真实密钥触发外部请求；不修改父进程环境。
const env = { ...process.env }
delete env.DEEPSEEK_API_KEY
const sdk = new HarnessSDK({ home, cwd: process.cwd(), env })
let notificationCount = 0

try {
  console.log('SDK 调用方 PID：', process.pid)
  console.log('Host 子进程 PID：', sdk.child.pid)
  assert.notEqual(sdk.child.pid, process.pid)

  // create 通过 stdio 请求子进程创建会话；调用方没有直接 new Host。
  const header = await sdk.create()
  console.log('会话 ID：', header.id)

  // run 组合订阅、提交、等待和读取；通知回调发生在本进程。
  const result = await sdk.run(header.id, '你好，044 SDK', event => {
    notificationCount++
    console.log('收到通知：', event.type)
  })
  console.log('最终回复：', result.text)
  console.log('结束原因：', result.ending.reason)
  console.log('收到通知数：', notificationCount)
  console.log('读回事件数：', result.events.length)
  assert.equal(result.text, '[离线演示] 你好，044 SDK')
  assert.equal(result.ending.reason, 'completed')
  assert.ok(notificationCount > 0)
} finally {
  // 关闭 stdin 发送 EOF，等待子进程释放 Host，再核对真实退出码。
  await sdk.close()
}

console.log('Host 子进程退出码：', sdk.child.exitCode)
assert.equal(sdk.child.exitCode, 0)
console.log('本次数据目录：', home)
````

### 创建 [`src/sdk-server.mjs`](../../../harness-own/src/sdk-server.mjs)

````javascript
import { Host } from './host.mjs'
import { DeepSeekModel } from './deepseek.mjs'
import { Peer, framing } from './rpc.mjs'
import { remote } from './remote.mjs'
import { resolve } from 'node:path'

// stdio只承担协议；日志必须走stderr。所有数据路径显式隔离。
const home = process.env.HARNESS_HOME
if (!home) throw Error('SDK服务必须显式设置HARNESS_HOME')
const modelFactory = process.env.DEEPSEEK_API_KEY ? () => new DeepSeekModel({ key: process.env.DEEPSEEK_API_KEY, model: process.env.DSH_MODEL ?? 'deepseek-flash' }) : undefined
const host = new Host(home, modelFactory), peer = framing(new Peer(), process.stdin, process.stdout)
remote(peer, host, 'local')
peer.once('closed', () => { void host.close().catch(error => { console.error(error); process.exitCode = 1 }) })
````

### 创建 [`src/sdk.mjs`](../../../harness-own/src/sdk.mjs)

````javascript
import { spawn } from 'node:child_process'
import { Peer, framing } from './rpc.mjs'
import { fileURLToPath } from 'node:url'

/** 自己的高层SDK只组合领域协议；不另起工具/历史/模型实现。 */
export class HarnessSDK {
  constructor({ home, cwd, env = process.env }) {
    if (!home) throw Error('SDK需要显式home')
    this.cwd = cwd
    // 普通测试不等待子调试器；只有专用配置明确打开时，Host才等待附加。
    const debugHost = env.SDK_DEBUG_HOST === '1'
    // 暂停断点时延长父进程的RPC等待；普通运行仍保留正常超时。
    this.requestTimeout = debugHost ? 3_600_000 : 10_000
    const runtimeArgs = debugHost ? ['--inspect-wait=127.0.0.1:0'] : []
    // 显式传递环境，禁止重读.env，也不让Host继承父调试器的监听地址。
    const childEnv = { ...env, HARNESS_HOME: home }
    delete childEnv.BUN_INSPECT
    delete childEnv.BUN_INSPECT_NOTIFY
    this.child = spawn(process.execPath, [...runtimeArgs, '--no-env-file', fileURLToPath(new URL('./sdk-server.mjs', import.meta.url))], { cwd, env: childEnv, stdio: ['pipe', 'pipe', debugHost ? 'inherit' : 'pipe'] })
    this.child.stderr?.resume()
    this.peer = framing(new Peer(), this.child.stdout, this.child.stdin)
    this.child.on('error', () => this.peer.close())
    this.closed = new Promise(resolve => this.child.once('close', resolve))
  }
  async create() { return await this.peer.request('session.create', { cwd: this.cwd }, this.requestTimeout) }
  async run(id, content, onEvent = () => {}) {
    const notify = message => { if (message.method === 'session.event' && message.params.sessionId === id) onEvent(message.params) }
    this.peer.on('notification', notify)
    try {
      await this.peer.request('session.watch', { id }, this.requestTimeout)
      await this.peer.request('session.submit', { id, content }, this.requestTimeout)
      const ending = await this.peer.request('session.wait', { id }, Math.max(120_000, this.requestTimeout))
      const events = await this.peer.request('session.read', { id }, this.requestTimeout)
      return { ending, events, text: events.filter(event => event.type === 'message/assistant').at(-1)?.data.content ?? '' }
    } finally { this.peer.off('notification', notify) }
  }
  cancel(id) { return this.peer.request('session.cancel', { id }, this.requestTimeout) }
  async close() { this.child.stdin.end(); await this.closed; this.peer.close() }
}
````

## 在 VS Code 追 SDK 启动的 Host

### 只运行或调试当前测试

1. 打开自己 PROJECT 中的 `tests/044-sdk.test.mjs`，在测试与实现中设置断点；配置已固定入口，不要求测试文件始终在前台。
2. 选择 **044：本节测试**，按 F5。这只调试父测试和父进程里的 SDK；Host 子进程正常运行，不等待另一个调试器。
3. 无论编辑器当前打开哪个文件，**044：本节测试** 都运行 `tests/044-sdk.test.mjs`。
4. 父进程的断点可以设在 `src/sdk.mjs` 的 spawn、create 和 run 中。想检查测试里的 result，就在测试中 `await sdk.run(...)` 后的断言处停。

普通验收的预期是 1 项通过，不应出现子进程等待附加的 Inspector 地址。旧版 `${file}` 配置可能误跑 SDK 源码；本节 program 已固定测试文件，看到类定义本身不代表执行了 create/run。

### 需要进入 Host 子进程时

1. 不用修改 `src/sdk.mjs`。选择 **044：SDK测试（等待附加Host）**，按 F5。这个配置明确设置 `SDK_DEBUG_HOST=1`，只有此时 SDK 才为子进程加入 `--inspect-wait`。
2. 此时父测试等待 Host 回复是预期现象；只启动这一项不会完成测试。子进程会打印自己的 `ws://127.0.0.1:端口/路径`，它与父调试器是两个不同地址。
3. 再选择 **Bun：附加子进程**，按 F5，粘贴子进程打印的完整 `ws://` 地址。本地已有自定义名称时，选择 `request: "attach"`、`url: "${input:bunInspectorUrl}"` 的那项。
4. 在 `src/sdk-server.mjs` 的 remote 调用、`src/host.mjs` 的 create/open 或子进程 Agent 中设置断点；如果调试器暂停，按 F5 继续。从“调用堆栈”选择父、子调试会话，确认分别观察到 SDK 和 Host。
5. 断点观察结束后继续执行，让测试进入 finally 并关闭 SDK。需要强制停止时，结束父、子两个调试会话，避免只关一边。

等待附加模式下，SDK 自己的 RPC 超时和 Bun 测试超时均延长到一小时；普通运行仍保留正常 RPC 超时。本节固定测试会明确设置 `SDK_DEBUG_HOST=0`，防止终端已有环境变量让它们误入等待模式。

如果此前按旧说明把 spawn 永久改成 `--inspect-wait`，请使用本章更新后的 SDK 完整代码。稳定复现旧问题的路径是：无条件加入 `--inspect-wait` → 只启动“当前测试” → 没有附加子调试器 → Host 不执行、父测试等不到回复。仅增加测试超时不能解决这件事。
