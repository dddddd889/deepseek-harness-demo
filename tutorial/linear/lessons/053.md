## 什么时候会用到这一页

桌面程序用外部浏览器登录时，攻击者替换state或重复提交回调，程序应在换票前拒绝；快捷键配置文件损坏时，也不能悄悄用默认值覆盖用户文件。这是两个独立的数据边界，本章尚未把它们放进桌面UI。

### 这次数据怎么走

```text
loginAttempt生成state/verifier/challenge → 拼授权URL → exchange校验回调路径和state → 单次标记consumed → fixed token请求；Shortcuts另走Store.read/write，读取已有版本后才接受修改。
```

### 创建 [`desktop/shortcuts.mjs`](../../../harness-own/desktop/shortcuts.mjs)

````javascript
import { Store } from '../src/storage.mjs'

/** 快捷键配置保持最后接受版本；坏文件不自动覆盖成默认值。 */
export class Shortcuts {
  constructor(path) { this.store = new Store(path) }
  read() {
    const value = this.store.read()
    if (value.version !== undefined && value.version !== 1) throw Error('未知快捷键版本，拒绝改写')
    return value.bindings ?? { send: 'CommandOrControl+Enter', cancel: 'Escape' }
  }
  write(bindings) {
    this.read()
    if (Object.values(bindings).some(value => typeof value !== 'string') || new Set(Object.values(bindings)).size !== Object.values(bindings).length) throw Error('快捷键重复或不合法')
    this.store.update(() => ({ version: 1, bindings }))
  }
}
````

### 创建 [`src/login.mjs`](../../../harness-own/src/login.mjs)

````javascript
import { randomBytes, createHash, timingSafeEqual } from 'node:crypto'

/** PKCE不把client secret放在桌面包里；账户后端必须明确配置。 */
export function loginAttempt({ authorizeURL, clientId, redirectURI }) {
  // verifier是本次登录的随机秘密，只在当前闭包保留，最后换token时提交；state独立生成，用于匹配回调。
  const verifier = randomBytes(32).toString('base64url'), state = randomBytes(24).toString('base64url')
  const url = new URL(authorizeURL)
  // 选择OAuth授权码流程：authorize返回的是一次性code，不是直接返回access_token。
  url.searchParams.set('response_type', 'code'); url.searchParams.set('client_id', clientId); url.searchParams.set('redirect_uri', redirectURI)
  // challenge = BASE64URL(SHA256(verifier))；授权URL只带摘要和state，不带原始verifier。
  // S256告诉授权服务器用SHA-256验证，服务器需要把challenge与后续签发的code绑定。
  url.searchParams.set('state', state); url.searchParams.set('code_challenge_method', 'S256'); url.searchParams.set('code_challenge', createHash('sha256').update(verifier).digest('base64url'))
  // 当前尝试是否已发起过兑换：这是本地一次性保护，不等于授权服务器已确认登录成功。
  let consumed = false
  return { url: url.href,
    /** 回调只能消费一次，state和redirect路径都必须匹配。 */
    async exchange(callback, tokenURL, fetcher = fetch) {
      // callback由回调接入层提供；先校验origin、路径和state，不能收到code就立即兑换。
      const result = new URL(callback), expected = new URL(redirectURI), actualState = result.searchParams.get('state') ?? ''
      if (consumed || result.origin !== expected.origin || result.pathname !== expected.pathname || actualState.length !== state.length || !timingSafeEqual(Buffer.from(actualState), Buffer.from(state))) throw Error('登录回调不合法或已消费')
      // code由授权服务器在用户授权后签发；它不是verifier、state，也不是最终token。
      const code = result.searchParams.get('code'); if (!code) throw Error('回调缺少code')
      // 发网络请求之前标记已消费；即使随后网络失败，也要新建登录尝试，不能重放当前回调。
      consumed = true
      // 将code和原始verifier交给token端点；服务器重新计算摘要并与保存的challenge比较。
      // 此函数是客户端，不在本地冒充授权服务器完成PKCE验证。
      const response = await fetcher(tokenURL, { method: 'POST', headers: { 'content-type': 'application/x-www-form-urlencoded' }, body: new URLSearchParams({ grant_type: 'authorization_code', client_id: clientId, redirect_uri: redirectURI, code, code_verifier: verifier }) })
      if (!response.ok) throw Error('登录换票失败：' + response.status)
      // 返回服务器的token响应；本章不负责把凭据落盘，也没有自动打开浏览器或接收系统回调。
      return await response.json()
    },
  }
}
````

## 补充知识：OAuth 登录中的 PKCE

<details>
<summary>展开：verifier、challenge、code、state 分别是什么，如何对应本节代码？</summary>

### 先区分本章已经实现什么

本章的 `loginAttempt` 是登录流程中的客户端辅助模块，还没有接到Electron登录按钮、系统浏览器和回调监听器。下面的浏览器与授权服务器是完整流程需要的参与方，不代表运行本章测试就会启动它们。标准依据见 [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636)。

PKCE全称Proof Key for Code Exchange，通常读作“pixy”。它把发起授权与兑换授权码绑定：即使授权码code被截获，没有本次尝试的秘密verifier，也不能通过正确实现的服务器校验取得token。它不是对用户密码加密，也不代替用户在授权服务器登录。

### 四个值不要混在一起

| 值 | 谁生成、何时生成 | 去哪里、在哪里保留 | 本节代码位置与用途 |
| --- | --- | --- | --- |
| verifier | 应用在loginAttempt开始时，用32个随机字节生成 | 闭包暂存；只在token兑换时提交 | randomBytes(32)加base64url；不是放在授权URL里的长期client secret |
| challenge | 应用根据本次verifier计算 | 放进授权URL；服务器与签发的code关联保存 | createHash('sha256').update(verifier).digest('base64url') |
| code | 授权服务器在用户授权后签发 | 通过回调交给应用，随后提交token端点 | result.searchParams.get('code')；客户端不自己生成它 |
| state | 应用在本次尝试开始时，独立用24个随机字节生成 | 授权URL发送，回调原样带回，应用与闭包中的值比较 | state与actualState比较，防止把不属于本次尝试的回调接进来 |

最终的access_token又是另一种值：由token端点在校验成功后返回，用来访问获准资源。不要把code、state或verifier直接当作access_token使用。

### 完整流程与本节函数的边界

```mermaid
sequenceDiagram
    participant A as 应用的loginAttempt与exchange
    participant B as 系统浏览器与用户
    participant S as OAuth授权服务器
    A->>A: 生成verifier与独立state
    A->>A: challenge为verifier的SHA-256摘要再做Base64URL编码
    A-->>B: 外层调用方打开attempt.url，携带challenge、S256与state
    B->>S: 用户登录并同意授权
    S->>S: 保存challenge，将其绑定到授权码
    S-->>B: 重定向到redirectURI，附code与state
    B-->>A: 外层回调接入调用exchange(callback, tokenURL)
    A->>A: 校验回调地址、state与consumed
    alt 回调错误、缺code或已消费
        A-->>A: 抛错，不发送token请求
    else 回调有效
        A->>A: consumed设为true
        A->>S: POST code与code_verifier
        S->>S: 校验code，计算verifier摘要并比较challenge
        alt code与verifier匹配且其他授权条件满足
            S-->>A: token响应
        else 校验不通过
            S-->>A: 错误响应，客户端拒绝兑换
        end
    end
```

浏览器打开、回调监听属于本章尚未实现的外层接入。`exchange` 只是接收callback字符串；向服务器请求token时，不会把用户密码交给本函数。

```text
loginAttempt(...)
  ├─ verifier随机秘密 → 计算challenge → attempt.url
  ├─ 独立state → attempt.url，同时在闭包保留
  └─ 返回exchange函数，闭包继续保存本次verifier、state、consumed

exchange(callback, tokenURL)
  → 检查callback的origin/path与state
  → 取服务器返回的code
  → consumed = true
  → POST code + code_verifier + client_id + redirect_uri
  → 授权服务器验证PKCE
  → 返回token响应或抛错
```

原始verifier不出现在授权URL里，但兑换时必须通过受保护的连接提交给token端点。标准中的S256方式使用 `BASE64URL(SHA256(ASCII(code_verifier)))`；本节verifier由base64url字符组成，使用UTF-8输入hash时与ASCII字节一致，digest('base64url')给出URL安全且无填充的编码。

state与PKCE分工不同：state帮助客户端关联本次回调，PKCE让服务器检查兑换者持有本次verifier。consumed是本地状态，不是第三种token；本实现发起兑换后即消费，网络失败也不会重用同一attempt。

### 用“授权码被拿走”理解为什么需要PKCE

```mermaid
flowchart TD
    C["授权服务器发出code"] --> A["原应用：持有code和本次verifier"]
    C --> X["截获者：只拿到code，不持有verifier"]
    A --> V["提交到token端点，服务器验证对应challenge"]
    V --> T["满足授权条件后返回token"]
    X --> F["无法提供匹配的verifier，兑换失败"]
```

这说明的是授权码拦截场景，不承诺能应对运行时秘密也一并被窃取的情况。verifier每次登录重新生成；不要打印真实code、verifier或token来观察流程。
