## 什么时候会用到这一页

模型先返回“先求和”的推理和分成两段的sum参数，Harness等整条assistant完整结束后才执行sum，再把推理、工具调用和工具结果放进第二次请求。若只收到半句文字就断流，保留中断文字，但不把截断工具JSON当成可执行调用。

### 这次数据怎么走

```text
Loop请求 → DeepSeekModel.toMessages → fetch /chat/completions → 015 SSE解析 → 按choice.index与tool.index累计正文/推理/参数 → 校验finish_reason及[DONE] → 交付tool、replay和finish → Tools.execute → 第二请求回放assistant与tool结果。
```

## 代码为什么放在这一层

替换的是“访问模型的实现”，不是Loop或DeepSeek服务本身。text增量可先显示；reasoning和工具参数先累计，收到完整结束才形成一条assistant。finish_reason说明这条回答为什么停，兼容接口的[DONE]说明流结束，二者不能混成一个标记。

## 同一次回复里的thinking、正文和工具调用，怎样拼到一起

**SSE只负责拆出事件；把这些事件拼成一条assistant消息的是本步的`DeepSeekModel.stream()`。**同一次HTTP请求里，thinking、正文和工具调用可以分别到达，也可以出现在同一条增量事件里。代码按字段分别收集，最后统一组装。

这里已经使用OpenAI兼容协议：推理放在`reasoning_content`字段，正文放在`content`字段，工具调用放在`tool_calls`字段。它们属于同一条assistant消息的不同字段，不是把几种内容混成一段文本，也不是Anthropic式的thinking内容块。

### 先沿一条具体回复走一遍

假设用户要求“计算2加3”，下表是同一个HTTP响应里的连续SSE数据。各条JSON都属于`choices[0]`，表中只展示关键字段；工具参数分片用JavaScript字符串写法展示。

| 依次收到的SSE数据 | 代码更新什么 | 累积结果 |
| --- | --- | --- |
| `delta.reasoning_content = "需要"` | `reasoning += ...` | 推理为“需要” |
| `delta.reasoning_content = "计算"` | 继续追加到同一个reasoning | 推理为“需要计算” |
| `delta.content = "我先算一下。"` | `content += ...`，同时产出text | 正文为“我先算一下。” |
| `delta.tool_calls`中工具index=0，id=`call-1`，name=`sum`，arguments片段为`'{"a":2,'` | 把身份、名称和参数分片放进`calls.get(0)`对应的对象 | 参数字符串暂时不完整，不能执行 |
| 同一工具index=0，arguments片段为`'"b":3}'` | 追加到该工具的json字符串 | 参数成为`{"a":2,"b":3}` |
| `finish_reason = "tool_calls"` | 保存到finish，仍继续接收 | 已知模型为什么停，还未确认数据发送完 |
| `usage`，同时`choices: []` | 产出usage，不新增回答内容 | 记录本次用量 |
| `[DONE]` | 设置ended并退出接收循环 | 开始完整性检查和最终组装 |

上面的中文推理和工具参数只是演示数据，便于观察拼接顺序，不代表真实模型一定按这些分片返回。同一个delta也可以同时携带多个字段；代码分别处理，不是互斥的`if/else`。

联系这些片段的关键，是变量在接收循环外创建：

```javascript
// 同一次请求一直复用这些累积变量；每次新请求会重新创建。
const calls = new Map()
let content = '', reasoning = '', sawReasoning = false, finish, ended = false
```

每处理完一条SSE事件，这些变量都还在。新片段继续追加进去，不会因为一条事件结束就清空。工具的Map按工具index分开保存参数，因此多个工具的分片交错到达，也不会拼到同一个参数字符串里。

### 两个index不是一回事

- `choice.index`：同一次请求里的第几份备选回答。本步只处理第0份，所以同一份回答的各个分片都使用`choice.index = 0`，不是每收到一片就加一。
- `delta.tool_calls[].index`：这份回答里的第几个工具调用。本步可以处理多个工具，用这个index分别累积它们的参数。

所以“一份回答中包含两个工具调用”是允许的，并不违反代码里的“只支持单个模型候选”。这里的“模型候选”就是备选回答，不是模型数量，也不是工具数量。

### 组装后的assistant长什么样

确认完整结束、校验工具身份、解析参数JSON之后，本步保存的`replay.message`会是这样的对象：

```json
{
  "role": "assistant",
  "reasoning_content": "需要计算",
  "content": "我先算一下。",
  "tool_calls": [
    {
      "id": "call-1",
      "type": "function",
      "function": {
        "name": "sum",
        "arguments": "{\"a\":2,\"b\":3}"
      }
    }
  ]
}
```

**推理、正文、工具调用都在同一条assistant消息里，各用自己的字段。**如果没有推理，省略`reasoning_content`即可，正文和工具调用仍可以在一起；只有正文时则不写`tool_calls`。有没有thinking不是判断工具调用的依据。

还要留意参数的两种形态：线上`function.arguments`是JSON字符串，适配器内部用`JSON.parse(call.json)`得到对象后，才以`kind: 'tool'`交给Loop。回放给模型时保存原参数字符串。

### 从适配器到下一次模型请求，谁负责什么

```mermaid
sequenceDiagram
    participant HTTP as 同一次HTTP响应
    participant SSE as sse解析器
    participant Model as DeepSeekModel.stream
    participant Loop as runTurn执行循环
    participant Tools as Tools执行入口
    HTTP->>SSE: 多块字节，包含多条SSE事件
    SSE->>Model: 逐条返回data字符串
    Model->>Model: 累积reasoning、content、calls
    Model-->>Loop: text片段收到就产出
    Note over Model: finish_reason先记住，DONE才退出接收
    Model->>Model: 校验完整结束，解析工具参数
    Model-->>Loop: thinking、tool、replay、finish各类Part
    Loop->>Loop: 保存一条message/assistant
    Loop->>Tools: execute或batch
    Tools-->>Loop: 工具结果
    Loop->>Loop: 追加独立的message/tool
    Loop->>Model: 下一次stream，传入最新历史
    Model->>Model: toMessages取replay.message还原assistant
```

有两次组装，分工不同：

1. `deepseek.mjs`把线上字段拼好，并通过replay保存完整的OpenAI兼容assistant消息。正文片段立即产出，thinking与工具调用等完整校验后再产出。
2. `loop.mjs`收集`partial、thinking、calls、replay`，一次性追加`message/assistant`到会话事实；工具执行结果随后以`message/tool`记录。

下一次请求时，`toMessages()`优先使用同协议的`replay.message`。历史里先是assistant提出调用，再是`role: tool`的执行结果；结果用`tool_call_id: "call-1"`关联原调用。工具结果不会塞回上一条assistant的正文或推理里。

## finish_reason和[DONE]，到底遇到谁才结束

**当前实现遇到`[DONE]`才退出接收循环；`finish_reason`只是先记住停止原因。**两者都收到后，还必须通过工具参数等检查，才能交付完整回复。

| 信号 | 表达什么 | 当前代码做什么 |
| --- | --- | --- |
| SSE空行，例如`\n\n` | 一条SSE事件结束 | 解析器产出这一条data，继续处理后面的事件 |
| `choice.finish_reason` | 这一份回答为什么停止生成 | 保存到finish，继续接收可能随后到达的usage |
| `data: [DONE]` | 该Chat Completions接口的发送结束标记 | 设置ended为true，break退出接收循环，再检查finish等信息 |

`[DONE]`由SSE解析器去掉`data:`前缀后返回，是一个普通字符串，不是JSON。因此代码在`JSON.parse(raw)`之前先判断它。

```text
收到finish_reason → 保存停止原因，暂不结束
收到usage         → 记录用量，继续接收
收到[DONE]        → 退出接收循环
                  → 检查finish_reason、工具身份与参数
                  → 组装完整assistant，产出finish
```

当前只允许停止原因之后再到达不含候选的用量事件（`choices: []`）；若之后又返回候选内容，会报“模型在finish_reason之后继续返回候选”。这避免把停止后的新内容悄悄接进已经结束的回答。

具体停止原因的后续行为：

- `tool_calls`：必须有工具调用，适配器转换成`finish: tools`，Loop执行工具后继续下一step。
- `stop`：正常完成当前回复；没有工具调用时，Loop结束当前turn。
- `length`：保留长度截断含义，Loop以length结束，不冒充正常完成。本步若同时收到工具调用但停止原因不是tool_calls，会拒绝交付这些调用。
- 其他原因：本步按异常处理，不统一伪装成stop。

只有finish_reason、没有[DONE]就断流，或者只有[DONE]、没有finish_reason，都会报“模型消息未完整结束”。已显示的正文不等于完整回复已经提交；出现异常或取消时，Loop会把已收到的非空正文记为`interrupted: true`，不会据此执行未完成校验的工具调用。

## 会不会把两次请求的响应拼到一起

**会跨同一个响应里的多条SSE事件累积，不会拿下一次HTTP响应来补上一次没收完的回复。**

```text
请求A → 多条SSE事件 → 一条assistant消息
                            ↓
                       执行工具、记录tool结果
                            ↓
请求B → 新的累积变量 → 下一条assistant消息
```

一次turn可以包含请求A和请求B，但每次`stream()`的reasoning、content、calls和SSE解析器的buffer都是独立创建的。跨请求传递的是已保存的历史消息；前一次缺少结束信息就报错，不会自动把两条响应流接起来。

````javascript
import { sse } from './sse.mjs'

/** 把会话历史转成OpenAI兼容消息；工具回复用tool角色关联tool_call_id。 */
export function toMessages(history) {
  return history.map(message => {
    if (message.role === 'tool') return { role: 'tool', tool_call_id: message.callId, content: JSON.stringify(message.content) }
    if (message.role === 'assistant') {
      // 只回放同一协议保存的消息，避免把旧Messages内容块发给Chat Completions。
      if (message.replay?.provider === 'deepseek' && message.replay.api === 'openai-chat') return structuredClone(message.replay.message)
      const value = { role: 'assistant', content: message.content ?? '' }
      if (message.thinking?.length) value.reasoning_content = message.thinking.map(block => block.text).join('')
      if (message.calls?.length) value.tool_calls = message.calls.map(call => ({ id: call.id, type: 'function', function: { name: call.name, arguments: JSON.stringify(call.arguments) } }))
      return value
    }
    return { role: message.role === 'system' ? 'system' : 'user', content: structuredClone(message.content) }
  })
}

/** DeepSeek的OpenAI兼容流；保留推理、工具调用与下一请求所需的assistant消息。 */
export class DeepSeekModel {
  /** baseURL是接口根地址；可含/v1，不重复添加版本路径。 */
  constructor({ baseURL = 'https://api.deepseek.com', key, model = 'deepseek-flash', fetcher = fetch }) {
    this.root = baseURL.replace(/\/+$/, '')
    this.key = key; this.model = model; this.fetcher = fetcher
  }
  /** 每次请求使用本轮快照；完整收到finish_reason和[DONE]后才交付工具调用。 */
  async *stream(request) {
    request.signal.throwIfAborted()
    // 请求历史、工具定义与用量选项，都使用Chat Completions字段。
    const history = toMessages(request.messages)
    if (request.config?.system) history.unshift({ role: 'system', content: request.config.system })
    const body = { model: request.config?.model ?? this.model, max_tokens: request.config?.maxTokens ?? 8192, stream: true,
      stream_options: { include_usage: true }, messages: history }
    if (request.tools.length) body.tools = request.tools.map(tool => ({ type: 'function', function: { name: tool.name, description: tool.description, parameters: tool.schema } }))
    if (request.config?.thinking !== undefined) body.thinking = structuredClone(request.config.thinking)
    if (request.config?.reasoningEffort !== undefined) body.reasoning_effort = request.config.reasoningEffort
    const response = await this.fetcher(this.root + '/chat/completions', {
      method: 'POST', signal: request.signal,
      headers: { 'content-type': 'application/json', authorization: 'Bearer ' + this.key }, body: JSON.stringify(body),
    })
    if (!response.ok) throw Error('模型 HTTP ' + response.status)
    if (!response.body) throw Error('模型响应没有正文')
    // 一次只请求一个候选；同一工具的参数可能分散在多条SSE事件里。
    const calls = new Map()
    let content = '', reasoning = '', sawReasoning = false, finish, ended = false
    for await (const raw of sse(response.body)) {
      request.signal.throwIfAborted()
      if (raw === '[DONE]') { ended = true; break }
      const event = JSON.parse(raw)
      if (event.error) throw Error(event.error.message ?? '模型流错误')
      if (event.usage) yield { kind: 'usage', ...event.usage }
      if (!Array.isArray(event.choices)) throw Error('模型流缺少choices')
      for (const choice of event.choices) {
        if (choice.index !== 0) throw Error('本步只支持单个模型候选')
        if (finish !== undefined) throw Error('模型在finish_reason之后继续返回候选')
        const delta = choice.delta ?? {}
        if (typeof delta.content === 'string') { content += delta.content; if (delta.content) yield { kind: 'text', text: delta.content } }
        if (typeof delta.reasoning_content === 'string') { reasoning += delta.reasoning_content; sawReasoning = true }
        for (const part of delta.tool_calls ?? []) {
          if (!Number.isSafeInteger(part.index) || part.index < 0) throw Error('工具分片缺少合法index')
          const call = calls.get(part.index) ?? { id: '', name: '', json: '' }
          if (part.id) { if (call.id && call.id !== part.id) throw Error('工具调用身份变化'); call.id = part.id }
          if (part.type && part.type !== 'function') throw Error('不支持的工具类型')
          if (part.function?.name) call.name += part.function.name
          if (part.function?.arguments !== undefined) {
            if (typeof part.function.arguments !== 'string') throw Error('工具参数分片应为字符串')
            call.json += part.function.arguments
          }
          calls.set(part.index, call)
        }
        if (choice.finish_reason != null) finish = choice.finish_reason
      }
    }
    if (!ended || !finish) throw Error('模型消息未完整结束：缺少finish_reason或[DONE]')
    if (!['stop', 'length', 'tool_calls'].includes(finish)) throw Error('模型异常结束：' + finish)
    if ((finish === 'tool_calls') !== (calls.size > 0)) throw Error('工具调用与finish_reason不匹配')
    // 完整验证所有工具后再交付，不能把缺字段或截断JSON当作可执行调用。
    const parsed = [], identities = new Set()
    for (const [, call] of [...calls.entries()].sort(([left], [right]) => left - right)) {
      if (!call.id || !call.name || identities.has(call.id)) throw Error('工具调用身份或名称不完整/重复')
      identities.add(call.id)
      const args = JSON.parse(call.json)
      if (!args || typeof args !== 'object' || Array.isArray(args)) throw Error('工具参数应为对象')
      parsed.push({ id: call.id, name: call.name, arguments: args, json: call.json })
    }
    request.signal.throwIfAborted()
    if (sawReasoning) yield { kind: 'thinking', text: reasoning }
    for (const call of parsed) yield { kind: 'tool', id: call.id, name: call.name, arguments: call.arguments }
    // DeepSeek工具续轮需要保留reasoning_content，不能只保存最终文字。
    const message = { role: 'assistant', content }
    if (sawReasoning) message.reasoning_content = reasoning
    if (parsed.length) message.tool_calls = parsed.map(call => ({ id: call.id, type: 'function', function: { name: call.name, arguments: call.json } }))
    yield { kind: 'replay', value: { provider: 'deepseek', api: 'openai-chat', message } }
    yield { kind: 'finish', reason: finish === 'tool_calls' ? 'tools' : finish }
  }
}
````

````javascript
import { id } from './events.mjs'
import { messages } from './projection.mjs'

/** 一个 turn 由多个模型 step 组成；工具调用和结果成组写入事实。 */
export async function runTurn({ session, model, tools, signal, config = {}, inbox, maxSteps = 20 }, content) {
  const turnId = id('turn')
  session.append('turn/start', { turnId })
  session.append('message/user', { role: 'user', content })
  let ending = 'limit', partial = ''
  try {
    for (let step = 0; step < maxSteps; step++) {
      signal.throwIfAborted()
      // 只在 step 边界注入 steer，不改正在传输的请求。
      let input
      while ((input = inbox?.claim('step'))) session.append('message/user', { role: 'user', content: input.content, source: 'steer' })
      const requestId = id('request'), history = messages(session.read()), catalog = tools.catalog()
      session.append('request/start', { turnId, requestId, step, config, messages: history, tools: catalog })
      const calls = [], thinking = []
      let replay
      let finish
      partial = ''
      for await (const part of model.stream({ messages: history, tools: catalog, config, signal, requestId })) {
        signal.throwIfAborted()
        if (part.kind === 'text') { partial += part.text; session.append('stream/text', { turnId, requestId, text: part.text }) }
        if (part.kind === 'thinking') thinking.push(part)
        if (part.kind === 'tool') {
          if (calls.some(call => call.id === part.id)) throw Error('重复工具调用身份')
          calls.push(part)
        }
        if (part.kind === 'usage') session.append('request/usage', { requestId, ...part })
        if (part.kind === 'replay') { replay = part.value; session.append('request/replay', { requestId, value: part.value }) }
        if (part.kind === 'finish') finish = part.reason
      }
      if (!finish) throw Error('模型流提前结束')
      if (calls.length && finish !== 'tools') throw Error('工具组与停止原因不匹配')
      session.append('message/assistant', { role: 'assistant', content: partial, calls, thinking, replay })
      partial = ''
      session.append('request/end', { requestId, reason: finish })
      if (finish !== 'tools') { ending = finish === 'stop' ? 'completed' : 'length'; break }
      if (!calls.length) throw Error('工具结束但没有工具调用')
      const execute = async call => {
        session.append('tool/start', { turnId, call }) // 每个副作用前先留下持久事实。
        return await tools.execute(call, { signal, session, turnId })
      }
      // 没装并发策略时仍走同一个执行门；装上后由元数据决定安全并发组。
      const results = tools.batch
        ? await tools.batch(calls, { signal, session, turnId, before: call => session.append('tool/start', { turnId, call }) })
        : await (async () => {
          const rows = []
          for (const call of calls) {
            try { rows.push({ ok: true, value: await execute(call) }) }
            catch (error) { rows.push({ ok: false, error: signal.aborted ? 'CANCELLED_OR_OUTCOME_UNKNOWN' : error.message }) }
          }
          return rows
        })()
      calls.forEach((call, index) => session.append('message/tool', { role: 'tool', callId: call.id, name: call.name, content: results[index] }))
    }
  } catch (error) {
    // 保留取消前真正收到的文字，但不伪装成成功完成。
    if (partial) session.append('message/assistant', { role: 'assistant', content: partial, interrupted: true })
    ending = signal.aborted ? 'cancelled' : 'error'
    if (ending === 'error') session.append('turn/error', { turnId, message: error.message })
  }
  session.append('turn/end', { turnId, reason: ending })
  return { turnId, reason: ending }
}
````

实际请求为`POST https://api.deepseek.com/chat/completions`，鉴权使用`Authorization: Bearer ...`。如果自己的兼容网关根地址已经包含`/v1`，代码会保留它并追加`/chat/completions`，不会重复添加`/v1`。这里不是只换URL：请求体、工具定义、工具回复和流解析也已改成Chat Completions格式。[DeepSeek官方调用示例](https://api-docs.deepseek.com/zh-cn/)

必须观察到`request/start → message/assistant（含calls）→ tool/start → message/tool → 第二次request/start → 最终message/assistant → turn/end`。模型实际返回的工具调用和完成原因以日志为准；缺Key时入口直接失败，固定模型或本地回声不算真API通过。HTTP 401/429、模型不存在、网关协议不兼容时，记录第一条真实错误。

流里每条JSON读取`choices[0].delta`：`content`是正文，`reasoning_content`是推理，`tool_calls`按index拼接工具参数字符串。收到`finish_reason`后还会等待`data: [DONE]`，缺少任一结束信息都报错；`tool_calls`才转换成Loop所需的`finish: tools`，`stop`和`length`分别保留正常停止与长度截断含义。[Chat Completions字段](https://api-docs.deepseek.com/api/create-chat-completion/)

本步把完整assistant消息保存在replay里，工具续轮时带回`reasoning_content`与原工具调用，工具结果使用`role: tool`和`tool_call_id`关联。DeepSeek在携带工具的请求中要求回传历史推理内容。[推理回传规则](https://api-docs.deepseek.com/guides/thinking_mode/)

这一步的真请求记录只证明当前路由，不证明 Files、其他 provider、长上下文和线上失败策略全都通过。后面的 `bun test` 仍运行固定模型与固定 HTTP 正文。
