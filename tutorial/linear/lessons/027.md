## 先分清Shell、管道、TTY和PTY

Shell是执行命令的程序；管道、TTY和PTY描述它连接输入输出的方式。持久Shell和PTY不是同一件事。

| 名词 | 白话理解 |
| --- | --- |
| Shell | 命令解释器，例如Bash、Zsh；负责解释`cd`、变量、重定向和启动程序。 |
| 管道（pipe） | 程序之间传递字节的通道，不提供终端设备的行编辑、窗口尺寸和前台进程组控制等机制。 |
| TTY | 操作系统提供的终端设备接口；名字来自早期电传打字机。 |
| PTY | 伪终端，用软件模拟终端；让连接它的程序感觉自己连接着真正的终端。 |

PTY分为master和slave两端：Harness通过master端读写；Shell及其子进程连接slave端，slave端表现为TTY设备。

```text
026：Harness ←→ stdin/stdout/stderr普通管道 ←→ Bash
027：Harness ←→ PTY master端 ←→ PTY slave端（TTY）←→ 子进程
```

026的“持久”表示多次调用复用同一个Bash进程，因此前一次的`cd`、`export`可以保留到下一次；即使用普通管道，也能做到这一点。

027新增独立的Terminal类，通过Bun原生PTY连接子进程，可写入输入、调整窗口尺寸、读取带游标的输出。连接PTY的程序通常会检测到`isTTY=true`，可能启用颜色、动态进度条或交互提示。普通管道可以分别收集stdout和stderr；两者连接同一个PTY时，输出通常混在同一终端流里。

本步测试启动的是打印TTY状态的Bun子进程，不是把026的Shell自动改成PTY Shell。当前教程也没有在后续完成原版持久Shell的PTY接线、起止marker提取和异常后自动重建；不能把本步PTY测试通过理解成这些功能已经补齐。

### 这行代码分别按了哪些键

```js
// 通过PTY依次发送进入编辑、输入文字、退出编辑、保存退出的按键编码。
terminal.write('ihello from PTY\x1b:wq\r')
```

| 字符串中的内容 | Vim中的操作 |
| --- | --- |
| `i` | 从普通模式进入插入模式。 |
| `hello from PTY` | 在插入模式下输入这段文字。 |
| `\x1b` | 发送Esc，离开插入模式，回到普通模式。 |
| `:wq` | 输入保存并退出命令。 |
| `\r` | 发送回车，执行`:wq`。 |

为什么`\x1b`可以当作Esc？终端通过字节传递键盘输入。按下Esc时，终端通常发送数值为27、十六进制为`0x1B`的字节。JavaScript字符串里的`\x1b`是十六进制转义，表示一个编码值为`0x1B`的字符，并不是反斜杠、x、1、b四个普通字符。

```text
terminal.write('\x1b')
  → 向PTY写入0x1B字节
  → Vim从终端输入中读到该字节
  → 按Esc处理，退出插入模式
```

这里没有模拟物理键盘，而是发送按键在终端中的编码。`\r`同理，是回车字符；并非所有按键都只对应一个字节，例如方向上键常见编码是`\x1b[A`，由多个字节组成，具体编码取决于终端模式和配置。需要发送字面文字`\x1b`时，JavaScript应写成`'\\x1b'`，这与真正发送Esc不同。

VS Code调试时，在本测试的`terminal.write`、`await terminal.closed`和文件内容断言处打断点。查看发送字符串中的`\x1b`（Esc）和`\r`（回车），以及`terminal.read().text`中的控制序列。测试有超时保护，长时间停在断点可能触发超时，需要重新运行。

### 创建 `src/terminal.mjs`

````javascript
/** Bun 原生 PTY：交互终端与上一部的管道 Shell 分开管理。 */
export class Terminal {
  chunks = [] // 保留带游标的文本窗口。
  offset = 0 // 游标按解码后的字符数累计。
  constructor(scope, command, args, options = {}) {
    const decoder = new TextDecoder() // 连续解码，避免中文跨字节块时变成乱码。
    /** 将完整文本追加到有界窗口。 */
    const append = text => {
      if (!text) return
      this.chunks.push({ offset: this.offset, text }); this.offset += text.length
      while (this.chunks.length > 1000) this.chunks.shift()
    }
    let finishOutput // PTY 的 EOF 与子进程退出是两个不同事件。
    const outputClosed = new Promise(resolve => { finishOutput = resolve })
    this.process = Bun.spawn([command, ...args], {
      cwd: options.cwd,
      env: { ...(options.env ?? process.env), TERM: options.name ?? 'xterm-256color' },
      terminal: {
        cols: options.cols ?? 80, rows: options.rows ?? 24,
        data: (_terminal, bytes) => append(decoder.decode(bytes, { stream: true })),
        exit: () => { append(decoder.decode()); finishOutput() }
      }
    })
    // 同时等进程与输出结束，不能为了尽早返回而丢掉末尾文字。
    this.closed = Promise.all([this.process.exited, outputClosed]).then(([exitCode]) => ({ exitCode }))
    scope.own(async () => {
      try { this.process.kill() } catch {}
      await this.closed
      this.process.terminal.close()
    })
  }
  /** 游标落后于保留窗口时明确报告，不能静默丢失输出。 */
  read(after = 0) {
    if (after < (this.chunks[0]?.offset ?? 0)) throw Error('终端游标已过期')
    return { offset: this.offset, text: this.chunks.filter(chunk => chunk.offset + chunk.text.length > after).map(chunk => chunk.text.slice(Math.max(0, after - chunk.offset))).join('') }
  }
  /** 写入同一 PTY 的键盘输入。 */
  write(text) { this.process.terminal.write(text) }
  /** 调整同一 PTY 的窗口尺寸。 */
  resize(cols, rows) { if (cols < 1 || rows < 1) throw Error('终端尺寸不合法'); this.process.terminal.resize(cols, rows) }
  /** 给终端子进程发送信号。 */
  signal(name = 'SIGINT') { this.process.kill(name) }
}
````

### 创建 `tests/027-terminal.test.mjs`

````javascript
import { test } from 'bun:test'
import assert from 'node:assert/strict'
import { Terminal } from '../src/terminal.mjs'
import { Scope } from '../src/scope.mjs'
import { mkdtemp, readFile, rm, access } from 'node:fs/promises'
import { tmpdir } from 'node:os'
import { join } from 'node:path'

test('真实PTY具有TTY属性、输出游标和退出事件', async () => {
  const scope = new Scope()
  const terminal = new Terminal(scope, process.execPath, ['-e', 'console.log("TTY="+process.stdout.isTTY);setTimeout(()=>process.exit(0),50)'], { cwd: process.cwd(), env: process.env })
  try {
    terminal.resize(100, 30)
    await terminal.closed
    assert.match(terminal.read().text, /TTY=true/)
    assert.equal(terminal.read(terminal.offset).text, '')
  } finally { await scope.close() }
}, 5000)

test('真实Vim通过PTY接收按键，保存文件并退出', async () => {
  // 依赖本机Vim；缺失时明确失败，不把跳过当作演示成功。
  const vim = Bun.which('vim')
  assert.ok(vim, '请先安装Vim，并确认终端可以运行vim --version')
  const root = await mkdtemp(join(tmpdir(), 'harness-vim-027-')) // 隔离演示文件。
  const scope = new Scope() // 持有PTY及其进程的清理函数。
  let timer // 演示自身的超时保护，失败时仍进入finally回收。
  try {
    const terminal = new Terminal(scope, vim, [
      '-N', '-u', 'NONE', '-i', 'NONE', '-n',
      // VimEnter发生后才通知测试：编辑器已就绪；不靠固定sleep猜启动时间。
      '-c', "autocmd VimEnter * call writefile(['ready'], '.vim-ready')",
      'demo.txt',
    ], { cwd: root, env: process.env })
    const interaction = async () => {
      const deadline = Date.now() + 3000 // 等待明确的就绪文件，限制等待时间。
      for (;;) {
        try { await access(join(root, '.vim-ready')); break }
        catch (error) { if (error.code !== 'ENOENT') throw error }
        assert.ok(Date.now() < deadline, 'Vim没有触发VimEnter就绪通知')
        await Bun.sleep(10) // 仅降低就绪检查频率，时间过去不代表就绪。
      }
      // i进入插入模式；Esc离开插入模式；:wq加回车保存退出。
      terminal.write('ihello from PTY\x1b:wq\r')
      assert.equal((await terminal.closed).exitCode, 0)
      assert.equal(await readFile(join(root, 'demo.txt'), 'utf8'), 'hello from PTY\n')
      assert.ok(terminal.read().text.length > 0, '应收到Vim的原始终端输出')
    }
    await Promise.race([
      interaction(),
      new Promise((_, reject) => { timer = setTimeout(() => reject(Error('Vim演示超时')), 4000) }),
    ])
  } finally {
    clearTimeout(timer)
    await scope.close()
    await rm(root, { recursive: true, force: true })
  }
}, 6000)
````
